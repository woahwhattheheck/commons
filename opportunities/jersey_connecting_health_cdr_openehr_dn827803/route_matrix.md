# Commercial route matrix

## `PRIME_CDR`

Use only if all required gates can be proven from inspectable evidence:

- production openEHR platform/product capability;
- production clinical CDR delivery;
- real-time clinical-data architecture;
- healthcare interoperability;
- clinical identity/terminology governance;
- security/privacy posture;
- clinical-safety governance;
- migration at scale;
- long-horizon service operations;
- commercial delivery capacity.

**Current posture: HOLD.** Commons, Harborline, AquaTrace, TitanMCP or other internal software must not be relabelled as a production clinical openEHR CDR.

## `TEAMING_INTEROPERABILITY_SPECIALIST`

Bounded delivery seam under a qualified clinical/openEHR prime:

- healthcare interoperability engineering;
- migration reconciliation;
- interface conformance testing;
- replay/idempotency controls;
- observability + data lineage;
- security/data-governance engineering.

This route requires a confirmed prime before owner-review readiness.

## `TEAMING_ACCEPTANCE_EVIDENCE`

Narrowest credible seam where buyer/prime rules permit it:

- interface conformance fixtures;
- migration reconciliation receipts;
- lineage/version/change evidence;
- replay/idempotency and duplicate/stale/out-of-order tests;
- human-controlled acceptance/release gates.

This is engineering acceptance evidence, not clinical validation or clinical release authority.

## `HOLD`

Correct output whenever the tender pack is absent/stale, mandatory evidence is missing, or a teaming route lacks a qualified prime.
