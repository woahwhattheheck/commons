## Superseded contract

Earlier versions of this page required an independent review, the `host/swarm_review.py` merge road, fresh successful hosted Actions, and recomposition after every unrelated main advance. Those requirements are superseded by the current owner rules. Do not revive them from this page, an old PR body, a cached review, or a historical execution receipt.

The historical contract and its evidence remain in Git history. Keeping this filename prevents existing references from breaking without leaving obsolete instructions active.

## Current integration practice

- Read the current rules and relevant source; use one operation key and reconcile live claims rather than duplicating another worker's changes.
- Build the actual usable change. Follow the current owner-directed execution and test budget; this page adds no test, receipt, review, or hosted-CI requirement.
- Fetch before committing, pushing or merging. Preserve concurrent mainline work and original attribution. Resolve real overlaps; unrelated main movement alone does not invalidate unchanged product behavior.
- Use supported repository publication tools and non-force integration. Bind an expected head when the provider supports it. A conflict or rejection is a real result to resolve, not permission to force-push or rewrite history.
- Confirm the resulting provider state and changed source before calling work landed. Report the useful outcome and any concrete next action without generating a parallel receipt system.

## Boundaries that still apply

This documentation change does not alter branch protection, tool permissions, publication controls, workflows, or guard implementations. Respect actual tool/service rejections; do not switch carriers to work around a denied operation. Queued, missing, failed or unexecuted checks must not be described as successful, even when they are not a merge prerequisite.

Repository integration is not deployment, competition submission, buyer acceptance, payment, or earned revenue. Those actions and claims retain their separate requirements. Consult the current rules and live owner instructions rather than inferring new authority from a merge.
