# Buyer-neutral workshare / proposal packet

## Positioning

OSU-CHS is asking for a foundational resident data-management system, not a generic chatbot. The useful TJLabs wedge is therefore **data authority + migration + auditability + secure application behavior**.

This package supports a prime, partner, or direct response with a bounded technical workstream:

1. **Legacy discovery and migration contract** — enumerate spreadsheet/ancillary inputs; map fields; produce conflict ledger; require explicit resolution rather than last-write-wins.
2. **Resident administration service** — canonical resident records, bounded administrative statuses, validation, versioned updates, role views, and controlled exports.
3. **Identity / least privilege** — map OSU roles into read/write field policy; preserve resident-self isolation; separate auditor from operational write authority.
4. **Audit + evidence** — append-only hash-linked mutation evidence, immutable receipt roots, deterministic reconstruction, and tamper hostiles.
5. **Analytics boundary** — aggregate reports without direct identifiers by default; any row-level analytics become an explicit buyer-authorized data product rather than an accidental export.
6. **Acceptance / migration proof** — synthetic fixtures first, then buyer-approved representative non-production samples; repeat normal + optimized tests; prove stale-write, role-escalation, conflict, and tamper failures.
7. **Handover** — schema dictionary, migration map, role matrix, API/operating runbook, incident/recovery procedures, and acceptance receipt.

## Commercial truth boundary

### We can truthfully show now

- an executable data-free prototype implementing migration conflict detection, RBAC-style field allowlists, optimistic concurrency, tamper-evident audit, aggregate analytics, and deterministic receipts;
- a source-pinned current qualification state with no runtime evidence input;
- a concrete staged implementation/acceptance method.

### Evidence needed before direct-prime readiness

- exact controlling RFP/addenda bytes and compliance extraction;

- owner-confirmed non-collusion certification authority;
- owner-confirmed portal registration and submission identity;
- pricing/legal/insurance/security commitments required by the controlling packet.

Until those exist, **TEAMING_REQUIRED is the commercially correct route**; current source cannot emit direct-prime readiness.
