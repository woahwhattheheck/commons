# Public-information windows for existing route commitments

This read-only consumer combines an **already inspected** route deadline with the
pinned engine's public shop-reveal calendar. It answers whether another public
observation arrives before an existing complete-program choice closes. It does
not compare routes, construct or call a producer, choose a route, predict shop
identities, price future output, or certify physical/economic feasibility.

BRIDGE-ROUTE owns the shared structural inspector in
[`cloud-route-frontier/commitment_window.py`](../cloud-route-frontier/commitment_window.py).
This directory adds the public-clock side of that interface rather than a second
prefix implementation. HAZEL retains production selection, DATE dated-receipt
ranking, ROUTE-FLOW market trajectories, and FIR the economic evaluator.

## Use with the existing controller inspection

Make the two source directories importable, then consume the same current
inspection rather than invoking it twice:

```python
from commitment_window import inspect_commitment
from information import from_commitment

boundary = inspect_commitment(
    existing_controller, target_route, observation["step"],
    decision_stop=configuration.get("episodeSteps", 720) - 1,
)
window = from_commitment(
    boundary,
    shop_count=len(observation["town"]["unlocked_shops"]),
    configuration=configuration,
)
```

`inspect_commitment` reports the original controller's one current predicate;
`from_commitment` calls neither the inspector nor a controller. Route aliases,
current incompatibility, unknown predicates and disagreements cannot become a
new waiting opportunity. The report retains current/target route fingerprints.
The inspection and clock must use the same exclusive decision range.

`information_window(...)` also accepts a caller-supplied inclusive deadline and
current compatibility directly. `future_shop_reveals(...)` is the standalone
public calendar. Integer configurations use the pinned engine defaults: 24
turns/day, an unlock every three days, eight shop **instances**, and 719 executed
decisions for a 720-step episode. Duplicate shops count individually. Invalid or
nonpositive timing values are rejected, not silently clamped. The clock does
not infer a missing current shop count or a future shop name.

`can_wait_for_next_reveal=True` means the next public reveal fits the supplied
structural window. It is not a decision to wait. `None` means the relevant
compatibility/deadline is unknown or there is no future reveal; it is never an
improvement or feasibility claim.

Standalone diagnostic, writing only JSON to stdout:

```sh
python -B information.py --now 226 --last-compatible-decision 226 \
  --compatible-now true --shop-count 3
```

## Recorded execution

`test_information.py` passes **13 methods**. The separate source-bound validator
passes nine actual shared-inspector/original-Arlene consumer cases. Its captured
engine invocation includes 67 unmodified end-of-day calls, four complete
interpreter boundary calls and seven initializations. Default/custom calendars,
the eight-instance cap, and both seats' next public observation agree. There are
zero policy action calls, full games, network calls or new game-seed reservations.
Synthetic engine fixtures are not reached-game or held-out evidence.

The joined cases distinguish a deadline before the next reveal from one that
still permits it. In the supplied MAIN-to-YARN case at decision 226, the next
public reveal is 288, a delay of 62 decisions, outside the inclusive deadline.
For the supplied MAIN-to-milk-exit inspection at 433 with deadline 577, reveals
504 and 576 fit. No original decision checkpoint or policy was retimed. These
are structural/source examples, not profitability findings.

Run the pure suite:

```sh
python -B -m unittest -v test_information.py
```

Use the already-retained source pack and engine cache for the exact integration
check. `KAG` is the existing source pack's `revenue/kaggriculture` directory;
`ENGINE` contains the three unchanged official source files. `BOUNDARY` is the
shared inspector, not a second copy generated by this component.

```sh
python -B validate_information.py \
  --arlene "$KAG/cloud-frontier-policy/next-panel/vendor/arlene.py" \
  --engine-cache "$ENGINE" \
  --loader "$KAG/20260907-offline-agent/evaluate.py" \
  --boundary "$BOUNDARY" > /tmp/information-validation.json
```

The validator loads explicit trusted local source modules and verifies the
recorded input identities before execution. Its legacy loader's network fallback
is disabled. It checks source and route-input preservation afterward.
`INFORMATION-VALIDATION.json` records the actual results and exact Git/SHA-256
identities. These checks apply only to this component, not repository-wide CI.
