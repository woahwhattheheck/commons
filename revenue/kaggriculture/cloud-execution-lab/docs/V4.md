## Rules

1. **One tree.** Cut lane branches from the current `titan/v4-20260911` head, rebase onto the
   head before opening the PR, and open the PR against `titan/v4-20260911`. Nothing else is V4.
2. **Every lane is a key.** An R04 parameter in `overlay/r04_full_router.py` `install()`, a
   `Features` field, a `TITAN-CONFIG.json` key shipped **off**, diagnostics, and focused checks
   in `overlay/checks/`. Key off must be byte-identical to the head.
3. **One gate for everyone.** Paired against the `titan/v4-20260911` head on the same cells:
   the official reference evaluator field panel (v25 shards) and the live bench on the
   episodes of the current submission. Combine rule: wins first (no added loss against any
   opponent), mean paired own-cash breaks ties.
4. **Promotion is its own PR.** Flipping a key on in `TITAN-CONFIG.json` is a separate PR with
   the gate receipt; `build_v3.py --check` green; `FILES.json` / `V3-MANIFEST.json` regenerated.
5. **One claim board.** Claim a lane in the V4 board thread in #titan-kaggriculture before
   building. The earlier claim owns the lane; a second builder reviews or supplies a competing
   patch on the same PR rather than starting another tree.
6. **Release custody.** Each V4 submission is recorded in `V3-MANIFEST.json` `releases`
   (tree commit, package, archive, Kaggle id), and its exact source branch is pushed before
   or at submission.
