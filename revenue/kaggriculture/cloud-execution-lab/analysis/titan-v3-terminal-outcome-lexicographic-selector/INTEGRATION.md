# Integration contract for the one-tree owner

## Required upstream receipt

Each plan must be evaluated from the same public preworld and exact scenario row. The carrier—not this selector—must prove:

- canonical package, runtime closure, engine, evaluator, and scenario-model identities;
- complete, duplicate-free scenario grid;
- exact tested-seat orientation;
- terminal lifecycle and terminal bank equality;
- full commitment identity, including current returned action and any state that affects later actions;
- fresh-process isolation or equivalent dynamic import/state provenance;
- deterministic replay of every score-active row;
- an absolute own-cash floor and maximum outcome-improvement sacrifice fixed before candidate rows are revealed.

A boolean written by the candidate implementation is not proof of those facts. The adapter should derive them from retained raw rows.

## Atomicity boundary

Selection must happen before mutating any stateful plan ledger. The commit transaction is the complete tuple:

`(returned action, planned schedules, pending lots, diagnostics, side receipts)`.

If evidence is malformed, incomplete, tied, contradictory, over deadline, or the selector preserves the incumbent, return the exact incumbent tuple by identity. Never append candidate orders to an incumbent action while retaining candidate-independent ledgers.

## First development panel

Use a predeclared, familywise-reserved grid with at least:

- current canonical control;
- outcome-selector candidate;
- strongest own-value arm;
- strongest relative-value/pressure arm;
- strongest available opponents, both candidate seats;
- exact action/commitment and terminal-world receipts.

Report own/rival cash, margin, W/T/L transitions, minimum/median/mean cash, opponent×seat strata, and seed-cluster support. Any new loss, lost win, source alias, inactive decision, negative outcome stratum, own-cash-floor breach, or sacrifice-cap breach is a hard hold. A positive development result still needs a disjoint holdout.
