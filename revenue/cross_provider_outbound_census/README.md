# Cross-Provider Outbound Census

`revenue.cross_provider_outbound_census` is a **preflight collision-history gate**
for Commons outbound work. It exists for one failure class: the same logical
opportunity can have several provider routes or official fallbacks, so a clean
search on one provider is not evidence that the opportunity has never already
been touched elsewhere.

A concrete example is a GitHub opportunity whose official fallback is email. A
worker can observe no GitHub submission while a prior Gmail fallback submission
already exists. The correct result is not "GitHub is clean"; it is **HOLD until
every registered provider/fallback route has a fresh, complete census**.

This module is additive. It does **not** replace the canonical
`revenue.outbound_connector_lease`, terminal send authority, provider-bound
consumer, organization-pressure gate, per-prospect lock, initial-outreach slot,
or post-send lease forensics.

## Authority ceiling

The strongest result is `CLEAR_FOR_DOWNSTREAM_GATES`. That means only that the
registered cross-provider history is complete and clean at the packet's bound
`trusted_now` and before `clear_until`. It does **not** authorize a send, acquire a
lease, establish qualification, prove provider acceptance, or permit any external
mutation.

Every packet states:

- `external_send_authorized: false`
- `lease_authorized: false`
- `provider_mutation_authorized: false`

The packet also carries the exact downstream
`outbound-connector-lease/v1/<sha256>` branch generated by the already-landed
canonical lease compiler. Recipient address, message body, subject, and provider
route are deliberately outside that logical lease seam.

## Input contract

The input is an inert JSON graph with five exact fields:

```json
{
  "schema": "commons-cross-provider-outbound-census/input-v1",
  "lease_input": {
    "schema": "outbound-connector-lease/v1",
    "buyer_scope": "example.org",
    "opportunity": {
      "kind": "external",
      "authority": "github.com",
      "id": "owner/repo/issues/123"
    }
  },
  "intent": {
    "provider": "github",
    "route_sha256": "<sha256 commitment to the route>",
    "claimant_scope": "swarm-z",
    "claim_scope": "issue-123",
    "requested_at": "2026-09-14T03:29:50Z"
  },
  "aliases": [
    {"provider": "github", "route_sha256": "<sha256>"},
    {"provider": "gmail", "route_sha256": "<sha256>"}
  ],
  "snapshots": [
    {
      "provider": "github",
      "status": "COMPLETE",
      "observed_at": "2026-09-14T03:29:55Z",
      "query_sha256": "<sha256 commitment to the provider query>",
      "covered_routes": ["<github route sha256>"],
      "events": []
    },
    {
      "provider": "gmail",
      "status": "COMPLETE",
      "observed_at": "2026-09-14T03:29:56Z",
      "query_sha256": "<sha256 commitment to the provider query>",
      "covered_routes": ["<gmail route sha256>"],
      "events": []
    }
  ]
}
```

Provider routes are SHA-256 commitments; the packet does not contain email
addresses, Slack destinations, GitHub URLs, subjects, bodies, or message text.
`lease_input` is validated by the existing canonical outbound lease compiler, so
the census cannot silently create a competing opportunity identity.

## Fixed freshness policy

Freshness is not caller-selectable:

- current intent maximum age: **300 seconds**
- provider snapshot maximum age: **300 seconds**
- a provider snapshot must be observed at or after the current intent
- a future snapshot or future intent always HOLDs
- `clear_until` is the earliest fixed expiry across the current intent and every
  required complete provider snapshot

A downstream worker therefore cannot safely reuse yesterday's clean packet for a
new send attempt.

## Fail-closed states

Each provider owning at least one registered alias must have exactly one snapshot.
The following produce deterministic `HOLD`:

- missing provider census
- `THROTTLED`, `UNAVAILABLE`, or `AMBIGUOUS` provider census
- stale, future, or pre-intent census
- missing or unknown route coverage
- unmapped current intent route
- prior provider send, human reply, or auto-reply
- unsubscribe or DNR evidence
- hard/soft bounce or provider rejection (route repair required)
- ambiguous provider effect

Known historical events are preserved in the packet even if the provider census
itself is throttled or incomplete. Incomplete coverage can never become a false
clean result.

## Compile

```bash
python -m revenue.cross_provider_outbound_census.census compile \
  --input /private/path/census-input.json \
  --trusted-now 2026-09-14T03:30:00Z \
  --out /private/path/census-packet.json
```

The output path is create-exclusive and final-component no-follow where supported.
A preexisting output is refused. Inputs reject mapping/list subclasses, duplicate
JSON keys, non-finite numbers, unsafe integers, excessive nesting, noncanonical
UTC, duplicate aliases, duplicate provider snapshots, duplicate evidence IDs, and
events on unregistered routes.

## Verify

```bash
python -m revenue.cross_provider_outbound_census.census verify \
  --input /private/path/census-input.json \
  --trusted-now 2026-09-14T03:30:00Z \
  --packet /private/path/census-packet.json
```

Verification checks the packet receipt and recompiles from the exact input
generation and exact `trusted_now`. Input drift, time drift, or packet mutation
fails closed.

## Required send sequence

A `CLEAR_FOR_DOWNSTREAM_GATES` packet is only the beginning:

1. ensure the packet is still before `clear_until`;
2. run all other qualification/suppression/pressure gates;
3. atomically acquire the exact `downstream_lease_branch` using the existing
   `outbound_connector_lease` protocol;
4. run terminal send authority immediately before provider mutation;
5. use the provider-bound send consumer;
6. preserve the connector lease until post-send evidence proves its terminal
   state.

Any missing or ambiguous evidence remains HOLD.
