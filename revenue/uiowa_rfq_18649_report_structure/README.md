# UIOWA-082 — Full RFQ-aligned final-report structure

**Status: PROPOSED REPORT STRUCTURE / NOT A UNIVERSITY FINDING.**
Everything in `fixtures/` and `examples/report_sample.md` is fiction, written to exercise the
structure. No statement here describes the University of Iowa, and no University evidence has been
collected.

Work order: *"Create the report production template covering executive summary, methodology, peer
benchmarking, cross-cutting themes, group/department recommendations, and supporting evidence. Map
every required report element to a section. … Complete when: the structure covers the RFQ
deliverables without adding a formal audit, employee evaluation, or vendor procurement report, and
can accept the planned matrix/register outputs."*

## What this is

Three things, and all three run:

1. **`content_map.json`** — the machine-readable map. 12 RFQ report elements → 15 sections →
   the exact datasets and field names each section consumes.
2. **`report_structure.py`** — loads that map, checks its coverage, verifies its field names
   against the registers other seats actually landed, and renders both the editable template and a
   populated synthetic sample from the same structure.
3. **`scope_guard.py`** — scans report prose for the three deliverables this engagement must *not*
   turn into: an audit/compliance verdict, an individual performance evaluation, a product
   procurement recommendation.

The content map is not a table in a document. A map that nothing reads drifts from the report within
one revision cycle; this one fails a build.

## Run it

```bash
cd revenue/uiowa_rfq_18649_report_structure

python3 report_structure.py --check                        # coverage checker
python3 report_structure.py --verify-workbench ../..       # field names vs. the landed registers
python3 report_structure.py --scope-guard                  # drift scan over template + sample
python3 -m unittest -v test_report_structure.py            # 55 tests

# regenerate the three artifacts in examples/
python3 report_structure.py \
  --render-template examples/report_template.md \
  --render-sample   examples/report_sample.md \
  --render-map-csv  examples/content_map.csv

# scan any report draft
python3 scope_guard.py path/to/draft.md --show-neutralized
```

All exit non-zero on failure, so any of them can gate a build. Python 3 standard library only; no
network at runtime.

## The coverage checker

It fails closed on four things, plus map-integrity checks:

| Code | Why it is an error |
|---|---|
| `UNMAPPED_ELEMENT` | A required RFQ element reaches no section — the report would ship without it. |
| `SECTION_WITHOUT_SOURCE` | A prose section that cites nothing. This is the quiet one: it is exactly where an unsupported assertion enters a report and then gets quoted back as a finding. |
| `UNKNOWN_DATASET` | A section consumes a register nobody built. |
| `FIELD_NOT_IN_SCHEMA` | A section names a field the real register does not have. |

Plus `DUPLICATE_SECTION_ID`, `ORPHAN_SECTION`, `DANGLING_ELEMENT_REF`, `MISSING_TRACEABILITY_RULE`,
`MISSING_UNKNOWN_RULE` (every section must state what it does with missing evidence), and
`MISSING_EXCLUSION` (the three out-of-scope deliverables must stay declared).

| `sdlc_evidence_worksheet` | `uiowa_rfq_18649_workbench/41-sdlc-evidence-worksheet.csv` |

`--verify-workbench` re-reads all seven and fails on `SCHEMA_DRIFT` if a pinned name has changed.
That is the *"can accept the planned matrix/register outputs"* completion condition as an
assertion rather than a promise. It also reports `SCHEMA_NEW_FIELDS` as a warning when an upstream
register grows a column this map does not consume yet.

Three datasets are `lane_local` — `finding_matrix`, `recommendation_register`, `theme_register` —
because no seat has landed them yet. Their field names are **reused** from the pinned registers
(`status`, `confidence`, `scope_limit`, `follow_up_question`, `evidence_ref` all already exist
upstream) and their identifiers follow the `EV-/OBS-/FND-/REC-` convention from UIOWA-023, so a real
matrix or register drops in without a rename pass. They are excluded from `--verify-workbench`
because there is no upstream file to verify against yet; that is stated, not hidden.

## The scope guard

Three drift classes, 15 rules, each carrying the matched span, why it drifts, and a suggested
rewrite:

- **`audit_verdict`** — `non-compliant`, `audit finding`, `material weakness`, `certifies`,
  `failed the audit`, `in violation of`.
- **`individual_evaluation`** — `performance rating`, `should be reassigned`, a role holder who
  `lacks the skills`, `Name Name's productivity`, `Name Name is underperforming`.
- **`product_procurement`** — `we recommend purchasing`, `preferred vendor`, `issue an RFP`,
  `per-seat price`, a named commercial product as the recommended action.

**The failure mode of a guard like this is over-firing**, and it happened on the first run. IE-05
detects a personal attribution by capitalisation — `[A-Z][a-z]+ [A-Z][a-z]+ performance` — but every
rule was compiled `re.IGNORECASE`, which turns that into *"any two words before the word
performance"*. It flagged the report's own correct sentence, *"a lead-time policy, not observed
deployment performance"*, as an individual performance evaluation. A guard that flags the report's
own prose gets switched off, and then it guards nothing.

Fixed by making `Rule` carry per-rule `flags` and compiling the two personal-name rules
case-sensitively, not by loosening the rule. `test_personal_name_rules_are_case_sensitive` is the
regression test.

The other half is `SAFE_CONTEXTS`. A report that must declare *"this assessment is not a formal
audit"* contains the word `audit`; a scope section that says *"no vendor selection is recommended"*
contains `vendor`. A match inside a sentence that is **disclaiming** the excluded deliverable is
reported as `NEUTRALIZED` rather than `FLAG` — still visible to a reviewer, not a build failure.
The shipped template and sample currently show **0 flagged, 4 neutralized**.

The guard reads *rendered* documents, not `content_map.json`, because raw JSON splits a record's
boundary context across lines. Every string in the map reaches the template, so nothing escapes.

## What the synthetic corpus demonstrates

Internally consistent: every evidence item points at a real finding, every recommendation cites a
real finding, every theme spans at least two findings across at least two groups. Asserted, not
claimed.

- **A real strength** — `FND-SYN-IAM-SEC-001`, the only `HIGH` confidence in the set. It is HIGH
  *because* the source is a bounded inventory query over an enumerated population of 14 accounts
  whose completeness basis is recorded. That is what made it checkable.
- **A real gap** — `FND-SYN-RIS-SEC-001`: a published standard requires an annual privileged-access
  review, and no completed review record was observed. Reported as `PARTIAL` / `LOW`, with the
  scope limit stating plainly that absence of a record in the material supplied is **not** evidence
  the review did not happen.
- **An unresolved conflict** — `FND-SYN-IAM-DEP-001`: an interview says every production identity
  change gets a change record; the export shows 3 of 14 emergency changes without one. Status
  `CONFLICT`, confidence `UNRESOLVED`, both sides retained. Its recommendation is investigate-first,
  because acting on either reading now would be acting on a guess.
- **Two kinds of unassessed** — `IAM/AI` is present with status `UNKNOWN` and
  `confidence NOT_EVIDENCED`; `RIS/AI` is absent from the matrix entirely. Both render as visibly
  unassessed and distinct from a weak result, and both are excluded from the assessed-cell count
  rather than counted as zero. The sample reports **10 of 12**, not 12 of 12.
- **A missing estimate** — `REC-SYN-IAM-AI-001` has `horizon UNKNOWN` and lands in an unsequenced
  bucket with the missing input named. It is not defaulted into `180+`, which would present a guess
  as a plan.
- **Peer rows that cannot be compared** — all three carry a real `comparison_status` from the
  landed vocabulary (`context_only`, `not_comparable_without_normalization`,
  `historical_not_current_benchmark`). No percentile, ranking or standing is stated anywhere.

Peer names are fictional (`Synthetic Public R1 University A`) on `example.invalid` URLs, so a
synthetic row can never be mistaken for the real peer research in
`19-metric-comparability.csv`.

## What is real, what is draft

**Real and runnable now:** the content map, the coverage checker, workbench schema verification,
the scope guard, both renderers, the CSV export, and 55 tests.

**Draft:** the section prompts and the narrative shape are a proposal for how the report reads. The
synthetic corpus is fiction. `SEC-14` (source and version register) is rendered as a pointer in the
sample rather than restating the landed registers.

**Consumed as input contracts, not rebuilt here** — these belong to other seats and this lane does
not edit them: the leadership executive-summary kit (UIOWA-081), the cross-cutting themes pack
(083), the prioritization calculator (084), the phased roadmap (085), the resource estimator (086),
and the accessible visual language (090). `SEC-01`, `SEC-10`, `SEC-11` and `SEC-12` are the seams
where those outputs land.

## University inputs that stay UNKNOWN

Nothing below has been collected. Each is an input the real engagement must supply; none has been
substituted with an assumption, a zero, or a default.

- The actual in-scope application inventory for ESS, RIS and IAM, and each service's criticality.
- Which of the twelve group × area cells will actually be reached, and which are out of scope by
  agreement.
- The real evidence register — interviews, configuration exports, change records, inventory
  queries — and each source's authorized locator.
- The freshness window the review team will declare for volatile evidence. The 120-day rule the
  workshare compiler uses for its synthetic model is not automatically a University standard.
- Whether the University wants peer context in the final report at all, and which peers.
- The report's audience split (leadership vs. practitioner), page budget, and house style.
- Who signs the report, and the review cycle before it is final.

## Scope boundary

This structure produces an assessment of current practice against reference frameworks used as
interview and artifact prompts. It is not a formal audit and issues no compliance determination,
certification or attestation. It assesses organizational practice; no statement rates, ranks or
evaluates a named individual. It describes capabilities the University may need; no vendor
selection or product purchase is recommended. The scope guard enforces all three on the prose.
