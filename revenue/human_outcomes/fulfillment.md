# Fulfillment and acceptance

These rules convert a fit-check request into a bounded paid job. They are operational defaults, not legal advice. The signed SOW controls when it differs.

## Common preflight

Before payment or confidential intake:

- name one buyer, one human outcome, one object, one acceptance rule, one clock, and one authorized reviewer;
- confirm the legal payee, scope, price, deposit, refund route, and collection rail privately;
- list supplied data and permitted tools;
- write what may not leave the buyer-controlled route;
- reject secrets or customer bytes posted to Commons;
- do not start the clock until every required input is usable;
- do not promise a deployment, compliance certification, attestation, or legal conclusion unless it is explicitly and lawfully in scope.

Default change rule: new objects, new systems, unavailable tests, source defects, or changed acceptance pause the clock and require a written change order.

Default cure/refund rule: one written revision or cure is included. If the provider still misses the locked acceptance, refund the unaccepted fixed fee. If the buyer changes scope, the original fee is not silently expanded.

## Backlog Rescue — one owned ticket

### Fit

Accept only when:

- there is one written issue and one authorized reviewer;
- repository access, branch rules, test commands, and CI behavior are known;
- the issue can reasonably fit in a preferably no-more-than-400-line change;
- production deployment, secrets rotation, data migration, and unrelated cleanup are excluded unless separately written.

### Delivery

1. Reproduce or characterize the issue.
2. Write the smallest implementation plan against buyer acceptance.
3. Use swarm agents for bounded research, implementation, and review.
4. Human-review every customer-facing diff.
5. Run agreed tests and CI.
6. Open one PR with risk, test, and rollback notes.
7. Produce the 8-bit state card: OPEN, BUILD, REVIEW, CI GREEN.
8. Buyer reviews; one written revision is included.

### Acceptance

The PR addresses the locked issue, available agreed checks pass, and the human review note names important decisions and remaining risks. Token count, number of agents, number of comments, and internal proof artifacts are not acceptance.

## Accessible meeting packet

### Fit

Accept a single packet up to 80 pages only after source inspection. Requote unreadable image scans, complex interactive forms, missing source content, heavy math, or a volume that cannot be responsibly completed in 48 hours.

### Delivery

- preserve source meaning;
- address document title, language, headings, lists, reading order, link purpose, images, tables, and bookmarks where applicable;
- provide an HTML or accessible-text companion;
- run automated and manual keyboard/reading-order checks;
- list unresolved source limitations in an exception log.

### Acceptance

The agreed files open, navigate, and contain the written structural work. This is remediation and QA, not certification or legal advice.

## Security questionnaire sprint

### Fit

Accept one workbook with no more than 150 questions, an authorized reviewer, and enough customer-owned evidence to answer responsibly.

### Delivery

- normalize duplicated questions;
- draft from customer-supplied policies, architecture, prior approved answers, and evidence only;
- cite the source for material claims;
- flag unknowns, missing controls, decision owners, and contradictions;
- never invent a certification, test, incident history, or control;
- return the workbook and a short blocker list.

### Acceptance

Every in-scope question is answered or explicitly flagged, material claims have an evidence pointer, and one authorized-reviewer revision is complete. Submission to the end customer is not included unless separately authorized.

## Pixel agent pack

### Fit

Lock 32x32 or 48x48, palette, three character adjectives, four state loops, file formats, commercial-use terms, and one reviewer. Reject copied characters, trademark imitation, or requests to impersonate another artist's living style.

### Delivery

- original character design;
- idle, think, error, and done loops;
- transparent sprite sheet and preview GIF;
- avatar and icon exports;
- grid/palette QA and a commercial-use note;
- one written revision.

### Acceptance

All agreed exports exist, match the locked grid and palette, and animate without broken frames. Eight-direction movement, large environments, and additional characters are new scope.

## White Box, SUBZERO, and compression

White Box remains governed by `commercial.json` and its private NDA/SOW. SUBZERO structural work and compression work may be used only when they advance a named customer outcome. Never substitute rollback evidence, hashes, structural receipts, or compression ratios for the human result the buyer authorized.

## Payment-state receipt

For every job, record these separately and never infer a later state from an earlier one:

`FIT_CHECKED -> SOW_SIGNED -> AUTHORIZED -> SETTLED -> PAID_OUT -> BANK_AVAILABLE`

Also record `DELIVERED`, `ACCEPTED`, `CURED`, or `REFUNDED` independently. A paid reference never proves delivery, and a delivery receipt never proves payment.
