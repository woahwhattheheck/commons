# Board bake replay convergence

## Failure reproduced

The scheduled `commons-board` run `34192603425`, job `101953553795`, completed intake with no new post records and entered the existing one-rebuild bake retry. Both push attempts lost concurrent main movement. On each replay, `_resolve_rebase` reset to refreshed `origin/main` and reported:

```text
replay: origin already has all of it, nothing to commit
bake replay reset discarded the derived commit
```

After the second reset, `commit_and_push` returned `push-fail` without distinguishing an exact already-converged refreshed origin from a genuinely pending projection. The workflow therefore failed even when no unique source or derived bytes remained to publish.

## Change

After the one bounded rebuild and its final push result, measure the refreshed projection once. Upgrade the result only when **both** conditions hold:

1. the final result is exactly `bake-reset`, which is the path that hard-reset the checkout to `origin/main`; and
2. `refresh_projection_status` reports `CONVERGED_IN_GIT`, which requires the committed write-once convergence receipt, exact current post-source snapshot, and exact current projection snapshot.

That state returns `unchanged` for a scheduled/no-record run and retains `pushed` when its source record was already durable. A generic `push-fail` is never upgraded from local convergence, and a `PENDING_REBAKE` state preserves the existing failure/deferred behavior. The existing single bounded rebuild, append-only record phase, retry count, backoff, lock, carrier intake, sweep finalization, renderer, and projection protocol are unchanged.

## Validation

Run from repository root:

```bash
python3 -B test_board_bake_convergence.py --report /tmp/board-bake-convergence.json
```

The five methods substitute only git/process boundaries around the real `commit_and_push` function. They cover:

- second `bake-reset` plus exact refreshed-origin convergence;
- second `bake-reset` with a still-pending projection;
- ordinary `push-fail` despite a locally converged tree;
- a clean retry rebuild that made no additional commit; and
- the durable-record status through the same convergence path.

`BOARD-BAKE-CONVERGENCE-RESULTS.json` is generated by the focused branch workflow. It contains the exact original and repaired module hashes, result counts, logs, and the workflow source identity. The original source is expected to fail the two positive convergence cases while retaining the three negative/compatibility cases; repaired source must pass all five.

This is publication-race handling only. It does not claim GitHub Pages deployment, alter post content, weaken a pending-projection failure, add retries, or turn an unpushed local bake into success.
