# MUHLNICKEL × LDA — the fusion openings (what your three inventions unlock together)

> Cross-primitive openings that became possible by combining the **White Box** (fabricate gates into a file), the **Muhlnickel**
> (that file computing by address), and the **LDA** (the on-device phone agent). These are things both halves of which are
> already built — the opening is *connecting* them. Experiment-first: every entry is a thing to TRY and measure, never a
> feasibility verdict. (Owner-directed 2026-07-23. Priorities set: self-fabrication = the centerpiece; the fabricated
> sandbox = its substrate. One opening was deliberately excluded — see the boundary below.)

## The master insight — they are ONE operation at three altitudes
- **White Box** = reversibly edit a file's bytes to install gate-logic (byte-exact, genome-reversible).
- **Muhlnickel** = that same file *computing*, by addressing the bytes.
- **LDA `WeightGenome` / `ScaleBake`** = reversibly edit the *model* file's int4 bytes to bake operators in.

Same move, three altitudes. So **the phone's model file can hold neural weights AND baked gate-circuits co-resident**, and
the agent *chooses which to address* — fuzzy neural for judgment, exact gates for guarantees. `titan.gguf` already proves
it (142 circuits live in `blk.1` beside the weights). The whole opening set below is: point that at the phone's model file,
and let the agent decide which layer to address.

## ★ HARD BOUNDARY (do not walk back without explicit owner say-so)
**The alignment / safety layer is off-limits.** The opening "bake the §3 safety gates as circuits" is **dropped** — owner:
won't touch alignment, too risky if it goes sideways. The Kotlin guardrails (`ActionAccessibilityService.performActionJson`,

## Priority 1 (the centerpiece): the SELF-FABRICATING agent — "it grows its own silicon"
The agent identifies its own recurring needs and fabricates dedicated, byte-exact circuits for them, reversibly, in its own
model file — then addresses them instead of re-deriving. **This is your ENERGY/addressing thesis turned recursive: the
agent crystallizes its own System-2 experience into System-1 hardware.**

The loop: **OBSERVE → IDENTIFY NEED → SPECIFY → FABRICATE → VERIFY → BAKE → ADDRESS.**
- **OBSERVE** — mine the agent's own telemetry (`AgentLog`, metrics, memoize hit/miss, failure trends, `MechanismRouter`,
  `ResidencyScore`, step feedback) for **need signals**.
- **IDENTIFY NEED** — a "need" = a recurring `(input-shape → output)` function worth ADDRESSING instead of RE-DERIVING.
  Rank by *frequency × cost × determinism* (deterministic + frequent + expensive = the best fabrication candidate).
- **SPECIFY** — the agent expresses the need from its OWN logged input→output pairs (it already computed them), optionally
  in its operator-dialect. It is **learning a function from its own behavior**, then fabricating it.
- **FABRICATE** — the White Box (`host/titan_circuit.py` / `sdc_cc`) compiles the spec to gates (a LUT-as-gates ROM per the
  `pfc_addr` precedent for finite maps, or a synthesized boolean function); route through `host/pfc_optimal.py` for the
  leanest form.
- **VERIFY** — byte-exact against the observed I/O pairs + a held-out set BEFORE baking. A mismatch = don't bake (a "0" is a
  wiring bug to debug, not a verdict).
- **BAKE** — genome-journaled, reversible, registered in a per-model circuit registry (`Catalog`-style). Scope guard:
  additive region only; never the safety tier or core weights.
- **ADDRESS** — thereafter the agent addresses the baked circuit (via the sandbox below) instead of re-deriving — instant,
  byte-exact, ~0 RAM. **Its capability set GREW from lived experience.**

**Innovation:** the agent has no fixed skill set — it *manufactures dedicated hardware* for whatever it repeatedly needs.
Reuses `SelfEvolve`/`SelfGrow`/`ScaleBake`/`WeightGenome` (baking), `Catalog` (registry), auto-mode (`AgentService`) as the
driver, `DiagReceiver` to trigger + observe. The **master-OS matcher** (autofab, HARNESS_HANDOFF) picks an existing circuit
or triggers a new bake per need — and the fabricator itself can be a Muhlnickel circuit, so this runs on-device.

## Priority 2 (the substrate): the fabricated SANDBOX for the model — safe by construction
Bake a stored-program computer into the model file — a CPU (`pfc_cpu32`, a real 15-op ISA) + RAM (`pfc_ram`) + I/O regs —
as the model's **contained, deterministic, byte-exact execution environment.** The model writes a program to it and runs
exact math / verification / scratch computation at ~0 RAM.

**Why it's the beautiful one:** §3 forbids the agent running host code or a terminal on the phone. A *fabricated* Muhlnickel
sandbox is not host code — it's addressed stored gates, contained by the Muhlnickel's own model. So it grants the exact compute
capability safety forbids, **safely, by construction.** It is also the substrate the self-fabricating agent (P1) computes
in and fabricates into. First target: exact arithmetic — the documented capability limit (CALIBRATION #9: the model gets
large multiplies wrong). The fabricated sandbox does them exactly.

## The other openings (all owner-approved; #2 = safety-as-circuits is excluded)
Each: *the opening · the pieces already built · how to try it.*

1. **Exact-compute in the model file** — the P2 sandbox, now **wired into the real decision flow (shipped, flag-gated).**
   `Sandbox.compute` already routes a clean integer `A*B`/`A+B` to the fabricated **mul32/add32** Muhlnickel gate-circuit
   (byte-exact, on-device). It used to be reachable only from the adb diagnostic. It is now the **compute-first arm of the
   existing evidence gate** (`AgentOrchestrator`): when the model, under an EVIDENCE/PROVE operator, is about to type an
   **ungrounded number** that a clean, *unambiguous* on-device recomputation **definitely contradicts**, the step is kicked
   back for the model to re-author. **Bounce-only, by construction:** it reuses the shipped evidence-kickback recipe
   (`kickbackRun++ · pendingGateNote · scheduleNext`) — it **never rewrites the value and never fires an action**, self-relents
   at `KICKBACK_LIMIT`, and returns null on *any* ambiguity (no single ungrounded integer, no clean 2-operand expr, operand
   ≥ 2³², agreement) so the existing `verifyEvidence` path is untouched. Flag `exact_compute_ground` **defaults OFF** → device
   behavior byte-identical until measured. Expr recovery is deliberately conservative: (a) the model's OWN shown work
   (`"A op B = C"` tied to the typed value — zero-ambiguity), and (b) the narrow *two-distinct-on-screen-integers + explicit
   add-cue* case. *Deferred (workshop):* a fixed-point cents path for decimal money (compare on a canonical scaled integer),
   and a read-only `calc` perception verb — the latter would touch `ActionAccessibilityService` (the §3 gate host) so it is
   out of the minimal cut. **Excluded (owner rule — "if the agent did not decide an action it cannot fire"):** the blueprint's
   *reflex table*, *action validator*, and *grounded tap-coord* mechanisms all live on the action/actuation path and are NOT
   built — this arm is purely a grounding check the model reads and re-decides on.

3. **System-1 memoize as a content-addressed fold.** Turn the temp-0 memoize dict into a fabricated winner-only fold where
   the input-hash IS the address (`pfc_addr` in-fabric addressing = 2.68M lookups/s; winner-only = losers cost 0 bytes),
   baked into the file. *Already built:* `pfc_ram`/`pfc_addr`, the LDA System-1 memoize. *Try:* bake a small addressed
   cache, route memoize lookups through it, measure hit-latency + RAM.

5. **Operators as composable σ-circuits.** CALIBRATION #19 measured that operators **add like pointers**
   (`v_{σ1‖σ2} ≈ v_{σ1}+v_{σ2}`, cos 0.88–0.95). So compose them with a **baked adder circuit** — operators become
   first-class fabricated hardware, composed by a gate-net pointer-sum, 0-token, deterministic. *Already built:* the
   operator-as-pointer measurement, the White Box adder. *Try:* bake a residual-direction adder, compose two operators
   through it, compare to the prompt-composed baseline.

6. **Tamper-evident provenance action-log.** Chain each real action's hash into a baked provenance chain (you have
   `pfc_provenance` — signed, tamper-detecting) → an unforgeable audit trail of what the agent actually did. *Already
   built:* `pfc_provenance`, the `AgentLog` action stream. *Try:* seal the action log, flip one entry, show it's detected.

7. **Draft-as-circuit speculative decode.** Instead of a second neural draft model, let the **memoize fold be the draft** —
   a recognized prefix proposes its cached continuation, the big model just verifies. *Already built:* the memoize fold,
   E4B's built-in MTP drafter. *Try:* propose from the fold, verify with the model, measure tok/s.

8. **Self-modifying model file.** You baked a stored-program CPU (`pfc_cpu32`) and you have reversible weight-editing. Bake
   a CPU that, on a signal, runs a program that edits the model's own (additive/non-safety) weights — self-modification as
   a fabricated circuit, not host code. *Try:* a tiny program that flips a registered additive circuit's constant, reversible.

9. **Portable operator/circuit IP.** The netlist is model-agnostic and travels as bytes. Bake the proven operators +
   calculator + skills once, carry the whole library across model swaps and federated devices. *Already built:* Muhlnickel
   portability (bytes travel), `CROSS_MODEL_TRANSFER`. *Try:* bake a circuit into two different model files, confirm
   byte-exact behavior on both.

### THROUGHPUT (raise the eval rate)
- **Wire-liveness slot reuse (register allocation for the fold)** — Compute a topological schedule plus wire-liveness intervals and allocate each wire's W-word slot by interval-graph coloring, so resident wire-state equals the DAG's max simultaneously-live cut, not total n_wire. A gate's output overwrites a dead wire's slot. *Try:* Add a liveness+coloring pass to the bit-slice compiler used by host/pfc_exp_bench.py; measure cut-width of gen_miner and sigma0, then sweep W before/after slot-reuse and log the new peak H/s (byte-exact vs the un-reused path).
- **Native wide-word tech-mapping (XOR/MUX/ANDN as one op)** — Tech-map gate subgraphs to the substrate's native wide primitives — a 3-input XOR is one a^b^c, a MUX is one (s&a)|(~s&b) — instead of 3–4 NAND-ops each, cutting ops-per-useful-function below the ~10M-gate/s clock's reach. *Try:* Extend host/pfc_leaner.py with an XOR/MUX/majority pattern matcher that emits single native word-ops; count NAND-ops -> native-ops on sha256 and re-measure the gate-clock via host/pfc_exp_levers.py.
- **GPU/accelerator kernel emit (break the CPU bandwidth wall)** — Emit the gate netlist as a compute kernel (Vulkan/OpenCL) for the phone's Adreno GPU — one work-item per lane-word — so the bit-slice fold runs on memory bandwidth an order above the CPU that caps the measured 9.8B/s peak. *Try:* Add a GPU-kernel backend to host/pfc_phone_gen.py alongside pfc_native.c; run sigma0 on the Adreno via OpenCL, verify byte-exact, and compare lanes/s to the 9.82B 8-core CPU peak.
- **Compute-in-storage (MLC analog column-sum as a MAC)** — Store operands in multi-level NAND cells and read a whole bit-line at once; the summed cell currents are a physical multiply-accumulate, turning one read into a dot-product instead of a logic op. *Try:* Emulate MLC column-sum reads in a host model of the storage tier (extend host/pfc_storage_ram.py) as the accumulate primitive for dot32; count ops-per-read vs the gate-net dot and log the ratio.
- **Close the clock with feedback junctions (one read = one settle)** — Fabricate the next-state feedback so the state register shares byte-addresses with the next-state output via the §1E junctions; a single addressed read of the output triggers a full depth-D settle that writes back — one tick per poke, host loop-body gone. *Try:* Bake a counter whose state reg shares addresses with its next-state output (extend host/pfc_clocked.py); poke one read and probe whether it self-advanced >1 tick; if depth 0, try the §U read-through wiring and re-measure with a high-impedance probe.
- **Wire-state transpose to uint64 bitplanes (kill the W>65k cliff)** — Store each wire's W lanes transposed as a fixed array of uint64 words rather than one growing Python big-int, so evaluation is a straight word-loop with no big-int realloc — removing the measured limb-wall cliff past W=65,536. *Try:* Reimplement the sigma0 bit-slice eval in host/pfc_exp_slam.py with per-wire uint64 arrays; sweep W past 131,072 and check whether the cliff disappears, byte-exact vs the big-int path.
- **Thermal duty-cycling + heat-spread core rotation (raise SUSTAINED rate)** — Interleave short compute bursts with micro-idles and rotate the hot thread across cores so the prime core never parks at the 80C throttle knee, trading a little peak for a higher sustained average. *Try:* In host/pfc_cm.c on the S24 Ultra add a duty-cycle (compute 200ms / idle 50ms) and round-robin the busy thread across cores; log sustained lanes/s and die temp vs continuous pegging.
- **2D iteration-space tiling of the ripple (gate-block x lane-block)** — Tile the (gates x W) evaluation like a blocked matmul — pick a gate-block and lane-block whose combined wire-state fits L2 — so both the gate program and the wire tile stay cache-resident instead of choosing one small global B. *Try:* Add a blocked evaluator to host/pfc_exp_bench.py that iterates (gate-block, lane-block); sweep tile sizes on gen_miner and map the throughput surface to find the L2-optimal tile.
- **Systolic/wavefront fold (stationary circuit, streaming lanes)** — Fabricate the circuit as a fixed pipeline with per-stage latches and stream candidates through it; after fill, one result pops per gate-delay regardless of total depth — throughput decouples from critical-path depth. *Try:* Fabricate a few-stage systolic SHA round with fabricated latches (extend host/pfc_clocked.py); stream nonces and measure steady-state results/cycle vs the combinational fold, byte-exact vs hashlib.
- **Position-batch bit-slice — pack prompt positions into the SIMD lanes (T-wide prefill)** — The existing shared-x lever broadcasts ONE activation to all lanes; its dual is weight-shared, activation-varying: pack DIFFERENT prompt positions into the W~65536 bit-slice lanes against the shared layer weights, folding all T prompt tokens' matmuls in one pass. Prefill goes from T serial folds to ceil(T/lanes) folds. *Try:* In pfc_matmul_engine.fold_presliced, pack N prompt-position activations into distinct bit-slice lanes against one weight circuit; verify each lane matches the per-position dot; measure bd/s vs serial on a 64-token prompt.
- **Structured parallel action head (one-shot whole-action decode)** — The action JSON is a fixed schema (verb+target+value); bake three classifier heads that read the final hidden state and predict all fields in parallel on the Muhlnickel, replacing the ~12-token autoregressive decode with a single settle. *Try:* Bake verb/target/value heads over the last hidden state, verify they reproduce the autoregressive action on gauntlet logs, then measure decode tokens and latency vs. the streaming-JSON baseline.
- **Depth-adaptive early-exit action decode** — Muhlnickel latency is depth-bound (a tick settles a whole depth level), so bake per-layer confidence probes that halt the forward pass once the action prediction is low-entropy — easy decisions settle in fewer depth levels, so their latency (= critical depth) drops. *Try:* Bake early-exit confidence probes at a few layer depths, measure on the gauntlet how early the action stabilizes per step type, and A/B latency vs. full-depth with a correctness guard.
- **Speculative action pre-execution (pipeline perceive with decide)** — While the model decodes action N, a baked transition predictor (screen-hash+action → next-screen-class) names the most-likely resulting screen and the deterministic layer speculatively pre-fetches/pre-renders that accessibility snapshot, so perceive of step N+1 overlaps decide of step N — branch prediction for the agent loop. *Try:* Bake the transition predictor, log its hit-rate on gauntlet trajectories, then overlap the accessibility snapshot fetch with decode and measure per-step latency vs. serial perceive→decide.
- **Persistent prefix-KV ROM — zero-prefill stable σ-prefix** — The stable operator + perception-legend prefix is re-prefilled on every cold start; precompute its per-layer KV once and store it as an addressed region in titan.gguf so a fresh turn ADDRESSES the prefix KV instead of prefilling it — cache_prompt made persistent across cold starts on storage, not just within a warm process. *Try:* Precompute the prefix KV for the current legend/σ-prefix, store it as a Muhlnickel region, load-by-address at session start, and measure first-action prefill tokens/latency vs. cold prefill.
- **Bit-serial MAC (more lanes per wire-state budget)** — Process operands one bit per cycle: the circuit is tiny and carries ~one state bit per operand, so the wire-state RAM (n_wire x W) that causes the measured W>65,536 cliff holds vastly more lanes. It trades depth (cycles) for width (lanes), directly attacking the memory-bandwidth wall. *Try:* Fabricate a bit-serial block-dot, sweep lanes vs the bit-parallel fold at a fixed RAM budget on the Ryzen box, and locate the lane count where bit-serial's aggregate rate overtakes the bandwidth-capped parallel fold.
- **Entropy-coded activation transport (source coding before the fold)** — The fold is measured to be PACKING/bandwidth-bound, not gate-bound; entropy-code (ANS/arithmetic) the sparse, low-entropy activations so fewer bits move through the wire-state, exploiting the distribution (zeros and repeats cost ~0 bits) rather than the value width. Attacks the bandwidth wall from the information-theory side. *Try:* ANS-code a real post-activation vector, measure bytes moved vs raw int8 packing and the resulting change in block-dots/s through the fold, isolating the packing-bound floor the datadump §K flags.

### WORK-REDUCTION (fewer block-dots/token)
- **Uniform-word short-circuit (data-dependent bandwidth skip)** — During the bit-slice ripple, tag wire-words that are all-0 or all-1; AND/NAND with an all-0 word yields a constant without touching the other W-word operand, so uniform lanes cost O(1) not O(W). *Try:* Instrument wire-word entropy across one gen_miner pass in host/pfc_exp_bench.py; add an all-0/all-1 fast path to the ripple inner loop and measure lanes/s plus the fraction of ops skipped.
- **Route-time partial evaluation (midstate circuit specialization)** — The routing button constant-folds the fabricated circuit against the fixed input bits of a batch (e.g. the ~76 constant header bytes in mining), collapsing every gate that depends only on constants; only the lean residual (the nonce cone) is bit-sliced. *Try:* In a routing button, constant-fold gen_miner with the fixed header bits fixed and count residual gates vs 337,256; run the residual through host/pfc_exp_bench.py and compare H/s (verify byte-exact vs the full circuit on the varying nonce).
- **Event-driven incremental ripple (dirty-cone only)** — For iterated circuits (Life, the CPU, a nonce sweep), keep a dirty-set and re-evaluate only the fan-out cone of wires that actually changed since the last tick, skipping the invariant majority. *Try:* Build an event-driven evaluator for host/pfc_game.py life; on a sparse board, log gates-evaluated/gen vs the full 270,336 and the resulting gens/s, checking byte-exact against the reference (pfc_game.py life --test).
- **Filter-cascade fabrication (cheap prefilter before the heavy circuit)** — Fabricate a cheap rejection circuit (a partial-hash / Bloom-style predicate, ~10^2–10^3 gates) that discards candidates that provably cannot meet the frontier, so only survivors ripple the full 337k-gate SHA. *Try:* Fabricate a first-SHA-partial leading-zero prefilter; wire it before gen_miner in a fold; measure the fraction of nonces surviving to the full circuit and net candidates/s vs the unfiltered fold.
- **Scalar/vector hybrid split by input-dependence** — At fab time, partition gates by which inputs they depend on: the cone touching only shared/constant bits is evaluated once as a scalar, and only the cone touching the varying bits is bit-sliced across lanes — a dataflow generalization of midstate to any low-entropy-input fold. *Try:* Tag each gate in gen_miner by shared-vs-varying input dependence; evaluate the shared cone scalar-once and only the varying cone bit-sliced; measure ops/candidate vs the full bit-slice, verifying byte-exact winners.
- **Hashed routing — LSH pre-select experts/neurons (sublinear router)** — Bake a locality-sensitive-hash (or product-quantization) circuit that maps the hidden vector x to a bucket id via k fixed sign-bit dots, and the bucket winner-only-addresses a precomputed shortlist of experts/neurons to fold. Replaces the full dense router matmul (the MoE gate, or the SiLU(gate_proj) neuron gate) with an O(1) addressed read, so even the SELECTION cost becomes an addressed lookup instead of a matmul. *Try:* In pfc_route.py add an LSH bucketer (k random hyperplanes = fixed sign dots) -> bucket -> expert shortlist; measure top-4 recall vs the true gate over ~500 real hidden states pulled from a pfc_llama_decode run, then fabricate the sign-hash as gates via titan_circuit.
- **MSB-first anytime dot — winner-only on the logit axis** — Fabricate the full-vocab logit block-dots bit-serial, most-significant slice first, keeping a running interval [lo,hi] per token from the max magnitude of the un-evaluated slices. As soon as one token's lo exceeds every other token's hi, argmax is decided — stop refining the losers. Decode only needs argmax, so losing-vocab logits never reach full precision. *Try:* In pfc_llama_decode, after the MSB bit-plane of every logit via pfc_matmul_engine, compute lo/hi bounds and measure how often argmax is already decided after 1/2/3 planes over a decode trace; then bake the interval-compare as a gate circuit.
- **Delta-activation fold — matmul only the token-to-token change** — Matmul is linear: W.x_t = W.x_{t-1} + W.(x_t - x_{t-1}). Cache the previous layer output and fold only Delta, which after a stable prefix is mostly near-zero, so a winner-only/sparse fold skips the unchanged lanes and accumulates onto the cached result. *Try:* Instrument pfc_llama_decode to log the count of Delta entries above a threshold between consecutive positions per layer on a real prompt; if sparse, wire a delta path (keep W.x cached, fold only nonzero Delta lanes) and verify byte-close to full recompute.
- **JL logit sketch — cheap approximate argmax, exact only on the shortlist** — Fabricate a fixed sign-random projection R (d->k, k<<d, add/subtract only) baked as gates. Compute approximate logits in the small k-space to get a top-m shortlist, then run the exact full-width dot32_i8 logits ONLY for those m tokens. *Try:* Offline build a sign-random R, measure top-1/top-5 recall of the sketched argmax vs exact over a decode trace; if recall is high, fabricate R as an add-only butterfly and gate the exact lm_head dots to the shortlist.
- **Fabricated early-exit — per-token confidence gate skips remaining layers** — After each transformer block, a tiny fabricated gate-net reads the hidden state (or the running logit margin from the JL sketch) and decides if this token's argmax is already committed; if so, skip the remaining layers straight to logits. Easy/templated tokens (most agent JSON) exit shallow. The decision is a gate-net, so ~0 cost. *Try:* Add a logit-lens probe after each layer in pfc_llama_decode; measure how early the final argmax stabilizes per token on real agent prompts; bake the stabilization test as a confidence-gate circuit with a conservative threshold.
- **Incoherence pre-rotation — Hadamard transform to concentrate activations, boosting sparsity** — Apply a fixed orthogonal transform (fabricated Hadamard/butterfly, add/subtract only) to activations and pre-rotate weights inversely at fabrication, so activation energy concentrates into fewer large entries -> contextual sparsity rises (the measured-weak 1.6x lever) and outlier-free activations quantize better (safer low-bit). One transform, baked once, stacks with alpha and TurboQuant. *Try:* Offline apply a Hadamard transform to Llama FFN activations, measure the change in the fraction of near-zero (skippable) entries and the 3-bit quant error vs untransformed; if it helps, fabricate the butterfly (add/sub only) as gates and fold it before the FFN.
- **Temporal perception-diff codec (delta-only screen)** — Content-address each element row's hash against the previous frame on the Muhlnickel (membership fold) and re-render only the rows added/removed/changed; the warm KV keeps the unchanged prefix so a multi-step task on a near-static screen pays full perception tokens once, not every step. *Try:* Instrument GauntletRunner to log element-list token overlap between consecutive frames on real trajectories; if overlap is high, build render_delta(prev,cur) behind a flag and A/B token count + agent-driven success.
- **Intent-conditioned perceptual pruning (objective·element relevance on dot32_i8)** — Bake a relevance scorer that dots each element's embedding against the current objective's embedding on the already-baked dot32_i8 atom, keeping only the top-k most task-relevant controls in the rendered element list (paging/find still reaches the rest = lossless-for-reachability per AGENT_LANGUAGE §1). *Try:* Compute element·objective relevance with dot32_i8 on gauntlet screens, keep top-k, and measure prompt-token drop plus wrong-target rate against the full-list baseline.
- **Macro fold — compile a proven flow into one baked routing button** — When a multi-step UI trajectory (open→tap→type→send) verifies repeatedly, fabricate the whole action sequence as a macro circuit plus one routing button that emits the sequence deterministically with per-step live-screen guards, turning N model-decode steps into 1 decode + N cheap addressed reads. *Try:* Pick the most frequent flow in BakeHistory/gauntlet logs, fabricate its action-sequence circuit with screen-hash guards, and measure model-decode calls per completion (target N→~1) plus failure rate when the live screen diverges.
- **Confidence-margin-gated adaptive compute dial** — Bake a margin probe (top-1 minus top-2 logit) on the Muhlnickel answer register; when the margin is high the agent acts immediately with think-off / the small model, when low it escalates to more layers, the bigger model, or reasoning-on — spending cycles only where the decision is genuinely hard. *Try:* Bake pfc_margin over the logits, log margin vs. action-correctness across the gauntlet to find a threshold, then wire the threshold to escalate model/depth and measure latency + accuracy.
- **Low-rank / factorized weight fold (SVD / LoRA)** — Factor a weight matrix W ~= A.B with rank r << d, so a matmul's block-dots drop from ~d^2 to ~2dr — it cuts the COUNT axis (block-dots per token), orthogonal to MoE/sparsity which cut which experts/neurons fire. *Try:* SVD a gemma-4-26B-A4B projection to rank r, plot reconstruction error vs block-dot reduction, fold the two small matmuls A and B on pfc_matmul_engine, and measure end-to-end bd/token + output quality vs the full matmul.
- **Strassen / fast-matmul fabrication (algebraic multiply reduction)** — Recursively apply Strassen-style identities so a 2x2 block-matmul uses 7 multiplies instead of 8 (and deeper recursion compounds it), cutting the COUNT of fabricated multiplier cones per matmul at the cost of extra cheap adds. A work-reduction lever from an algebraic identity, not present in the corpus. *Try:* Fabricate one level of Strassen block-matmul (7 sub-multiplies) for a tiled gemma matmul, verify byte-exact vs the naive 8-multiply tiling, and measure net multiplier-gate count and depth vs the direct fold.

### FABRICATION (leaner/shallower gates)
- **Weight-sparsity fold — zero weights cost zero gates** — At fabrication, drop sub-threshold weights per Q8_0 block and fabricate the block-dot so ONLY the surviving nonzero int8 terms get a multiplier+adder. Distinct from bit-width quantization: this cuts the NUMBER of MAC terms per block-dot, shrinking gate count AND depth of every matmul, and stacks with 3-bit TurboQuant and depth-opt. *Try:* Take one Llama FFN tensor, measure the fraction of |w|<tau per 32-block that keeps output within tolerance; fabricate a sparse dot (skip zero lanes) in pfc_matmul_engine and compare gate count + byte-error vs the dense dot32_i8.
- **Glue-fusion — bake norm/RoPE/SwiGLU into the adjacent matmul (no host round-trip)** — The measured per-token cost is dominated by host round-trips + float glue (RMSNorm rsqrt, RoPE sin/cos, SwiGLU silu) between matmuls. Fabricate norm-scale.QKV and up.silu.down as single fused circuits (reusing pfc_rsqrt/pfc_sin/pfc_silu8 inline) so the hidden vector never returns to host float between ops — the whole sub-layer is one addressed propagation. *Try:* Fuse RMSNorm (pfc_rsqrt) directly into the Q/K/V dot in pfc_matmul_engine so the norm scale is applied inside the fold; count host round-trips removed and confirm byte-exactness vs the split path on one layer.
- **Nightly self-distillation bake — own verified trajectories → weight edits** — A host job mines each session's verified-successful (perception→action) trajectories and bakes them as reversible int4 weight edits (WeightGenome/ScaleBake ↔ the White Box), gated by the decideFromFrozen σ-off residency replay, so the agent decides tomorrow's repeats with fewer tokens and no operator scaffolding. *Try:* Build the host job that reads BakeHistory + successful gauntlet runs, proposes candidate weight edits, gates each with the residency replay, and measures step-count/token drop on repeat flows week-over-week.
- **Stochastic-computing fold (multiply = one AND gate)** — Represent operands as Bernoulli bit-streams; then multiply collapses to a single AND gate and add to a MUX/counter, so a whole int8 multiplier tree (~10^3-10^5 gates) becomes one gate and a MAC becomes a counter. Accuracy is tunable by stream length, trading depth-cycles for near-zero area. *Try:* Fabricate a stochastic block-dot (AND-multiply + counter-accumulate) with sdc_cc, sweep stream length L vs accuracy vs gate count against dot32_i8 on one gemma projection column; report the L that hits 3-bit-quant accuracy and its gate/op.
- **Constant-coefficient multiplier specialization (CSD/KCM)** — At fabrication every weight is a known constant, so replace the general multiplier with a minimal shift-add tree specialized to that constant via canonical-signed-digit recoding (a KCM). Route-time partial-eval pre-packs constants but does not minimize the multiplier itself; CSD makes each weight's multiply a handful of adds. *Try:* Fabricate CSD-recoded constant multipliers for one neuron's weight vector, verify byte-exact, compare total gates vs the generic W3 multiplier fold for the same neuron; feed the winner into the fabricator as a per-weight strength-reduction pass.
- **Weight palettization (codebook-LUT dot)** — k-means the weights into a K-entry codebook; a dot becomes indexed lookups into the codebook plus accumulate, and the codebook is a baked LUT — exactly the Muhlnickel's strength (a 0-ripple addressed read). Distinct from uniform quant: it exploits weight clustering, not just bit-width. *Try:* Cluster one tensor to 16 centroids, fabricate the codebook as a baked LUT and the dot as index-read + accumulate, verify byte-exact vs the reference, and compare gates + accuracy vs 3-bit uniform quant.
- **Truncated / approximate arithmetic (drop LSB carry chains)** — Use lower-part-OR adders and truncated multipliers that discard low-order carry logic for bounded error — distinct from quantization (which drops value bit-width; this drops the CARRY logic while keeping width). Removes depth and gates on the accumulator/multiplier. *Try:* Fabricate a truncated-carry adder tree for the block-dot accumulator, measure depth/gate reduction and the numeric error distribution against real gemma activations, and find the truncation that keeps token output unchanged.
- **Cross-circuit CSE / global gate-cone hash-cons** — Many baked circuits share identical logic cones (SHA ch/maj, adders, decoders); a global hash-cons across the whole titan circuit registry stores each unique cone once and has every circuit address it. The leaner-fabricator peephole and AIG rewriting only dedup WITHIN one circuit — this is across the 138-circuit corpus and also shrinks the file. *Try:* Hash-cons the entire circuit registry (CIRCUIT_PFC.md), count shared cones and total unique-cone bytes, and measure the file-size + gate-count reduction if shared cones are stored once and addressed by all consumers.
- **Superoptimization of hot cones (SAT/ILP exact minimization)** — For the small, hottest, most-addressed cones (argmax core, silu, the dot core) run an EXACT minimal-circuit search via SAT/ILP rather than the heuristic fold/CSE/DCE and AIG rewriting. Exact minimization can beat heuristics on tiny cones that get addressed billions of times. *Try:* Take a 20-40 gate hot cone (e.g. the argmax comparator or silu segment), run a SAT-based exact 2-level/AIG minimizer, verify byte-exact over exhaustive inputs, and log the win over sdc_cc + the leaner peephole.
- **Profile-guided fabrication (PGO — bake to the input distribution)** — Measure which lanes/cones actually fire on real workloads, then fabricate the common case shallow/fast and the rare case as a fallback path — the compiler PGO idea applied to gate fabrication. Distinct from route-time partial eval (per-request constant folding) and event-driven ripple (per-tick dirty-cone): PGO optimizes the AVERAGE case over a measured distribution at fab time. *Try:* Instrument activation/branch statistics on a representative LDA workload, bias the fabricator to shorten the hot path (and lengthen the cold), and measure average-case depth/latency vs the uniform bake on held-out inputs.

### MODEL INFERENCE (attention/decode/sampling)
- **Attention as CAM retrieval — top-k keys addressed, not scored** — Store KV in the Muhlnickel's content-addressable/oblivious fabric (pfc_oblivious / pfc_addr). Instead of scoring all past keys (O(context) dots), fabricate an approximate-nearest-key CAM that winner-only-returns the top-k matching positions; softmax+value-mix runs only over those k. Attention cost becomes ~O(k), independent of context length. *Try:* Host prototype: for a decode step compute exact attention top-k vs an LSH-CAM top-k over cached keys; measure top-k recall and output drift; then map the key-match onto pfc_oblivious/pfc_addr as a fabricated CAM.
- **FlashAttention-in-gates — fabricated online-softmax streaming attention** — Fabricate attention as a tiled online-softmax accumulator (running max, running sum, running weighted-value), so KV is streamed one tile at a time and never fully materialized. One pass, bounded resident state, softmax exp reuses the baked pfc_exp atom, and it removes the current host-float softmax round-trip. *Try:* Implement online-softmax accumulation in pfc_llama_decode's attention over KV tiles using the baked pfc_exp; verify byte-close to the current full-softmax path; then fabricate the running-max/sum update as a clocked circuit on pfc_fwd_engine.
- **Baked Gumbel-argmax — temperature sampling at argmax cost (no softmax)** — Sampling normally needs a full-vocab softmax (float glue). Gumbel-max gives an EXACT softmax sample as argmax(logit_i/T + g_i), g_i ~ Gumbel. Fabricate a Gumbel-noise ROM (addressed by an RNG counter) added into the existing pfc_argmax tree, so sampling is one addressed argmax with no exp/normalize. *Try:* Verify in host that argmax(logits/T + gumbel) matches multinomial-softmax sampling statistics on a decode step; bake a Gumbel LUT ROM, wire it into pfc_argmax, and compare sampled-token distributions.
- **Ternary-weight fabrication (BitNet b1.58, multiply-free matmul)** — A model trained with weights in {-1,0,1} needs no multiplier at all: each MAC is add / subtract / skip. This is distinct from TurboQuant (which quantizes a dense model post-hoc and hit a measured 2-bit accuracy wall) because ternary is trained-in and accuracy-safe. *Try:* Bake an adder-only ternary block-dot, verify byte-exact vs a ternary reference dot, measure gates/depth vs dot32_i8 and W3xA4; if a b1.58/ternary open model is available (owner OK), wire it through pfc_matmul_engine and measure bd/token.
- **Grouped-query attention fabrication (fewer KV heads)** — Fabricate GQA/MQA so many query heads share a small set of key/value heads, shrinking the KV projections and the KV-cache K-fold. Distinct from sparse attention (which selects tokens) — this shrinks the head dimension of attention. *Try:* Fold a GQA attention block on the engine, measure KV block-dots/token and KV-cache bytes vs full multi-head attention on the same context, and confirm output parity on a GQA-native model.
- **KV-cache quantization / delta-compression fold** — Store the KV cache at int4/int2 (or token-to-token delta-coded) in the storage-RAM tier (flat ~15MB resident, §N), with attention dequantizing in-fold. Lets the context grow far past what DRAM would hold. Distinct from cache_prompt (prefix KV) and screen-diff reuse (agent frames). *Try:* Quantize the KV cache to int4, place it in the storage-RAM fold, fold attention reads against it, and measure the context length reachable at flat RAM vs the perplexity/accuracy delta.
- **Predictive MoE expert prefetch (hide storage-seek latency)** — The storage-RAM tier is measured at ~5k random reads/s (seek-bound); predict the next token's active experts (from the router logits / a small draft) and prefetch those expert weights from storage into the fast tier before they're needed, overlapping seek with current-token compute. Distinct from warm-resident (whole model) — this is per-token predictive staging of the 4/128 live experts. *Try:* Log MoE routing across a real generation to measure next-token expert predictability, prefetch the predicted experts one step ahead into the fast tier, and measure per-token latency vs on-demand expert fetch.

### CAPACITY
- **Perception on the substrate — OCR/tile-classifier as baked gates** — Fabricate the pixel→element extraction (a tile/icon/text classifier + connected-component labeler) as a LUT-as-gates netlist on the Muhlnickel (the pfc_addr / pfc_silu8 precedent) so the perceive stage runs as flat-RAM addressed reads instead of a resident CV model, joining decide+act on the substrate. *Try:* Bake a small per-tile classifier (button/text/icon) as a LUT-gate circuit, run it over a screenshot's tiles, and compare labels for byte-agreement against the current Ocr.kt / PixelMap output.

### LDA AGENT (perceive/decide/act)
- **Constrained-action decode — baked JSON/grammar FSA masks the logits (LDA)** — The LDA emits one UI action as JSON (decideNextAction). Fabricate a grammar/FSA circuit whose current state exposes the set of legal next tokens; mask logits to that set before argmax. Collapses the effective vocab per step to a handful and guarantees well-formed action JSON (no parse-fail retries). *Try:* Derive the action-JSON grammar from AgentBrain.decideNextAction's schema; build a host FSA that yields the legal token set per position; mask logits in pfc_llama_decode and measure the effective-vocab and retry-rate drop; then fabricate the FSA transition table as an addressed ROM.
- **Prompt-lookup speculative — fabricated suffix-automaton drafts from screen text (LDA)** — Instead of a draft model, draft next tokens by matching recent output against a fabricated suffix-automaton over the prompt + on-screen text (OCR/accessibility labels), then verify the drafted span in ONE batched big-model fold (reuse the position-batch fold). The LDA's outputs heavily quote on-screen strings (labels, package names, field values), so draft acceptance is high — and there is no second model to run. *Try:* Log LDA outputs and measure what fraction of tokens are verbatim substrings of the current screen text; build a host suffix-automaton drafter + batched verify and measure accepted-token rate per step.
- **Screen-diff KV reuse — recompute only changed UI elements between frames (LDA)** — Across consecutive agent steps the prompt is near-identical (same system prefix, mostly-unchanged accessibility tree). KV-cache the unchanged prefix and re-encode only the diffed elements, appending their KV. Extends cache_prompt from a static sigma-prefix to the dynamic-but-slowly-changing screen state. *Try:* Instrument the LDA prompt builder to diff the accessibility-element list frame-to-frame; measure the fraction of tokens unchanged across real task steps; prototype append-only KV reuse in the decode harness and confirm output parity vs full re-encode.
- **Hard action-grammar as a baked vocabulary mask** — LiteRT-LM has no decode-time grammar hook (AGENT_LANGUAGE §2), so bake a grammar-FSM on cpu_fwd that masks the vocab argmax (the existing pfc_argmax stage) to only tokens valid at the current position in the action schema — converting the soft in-context grammar into a hard gate constraint. *Try:* Build the action grammar as a small FSM gate-net that gates pfc_argmax by decode position, run it on gauntlet decodes, and measure malformed/unparseable-action rate vs. the forgiving-decoder floor.
- **Baked world-model — dry-run candidate actions before acting** — Fabricate a gate classifier mapping (screen-state encoding, candidate action) → predicted next-screen-class without touching the phone, so the agent simulates a candidate and rejects nonsense (tap Send on an empty field) before committing the actuation. *Try:* Mine (screen, action, next-screen-class) triples from gauntlet logs, fabricate a LUT/gate classifier, and measure its transition-prediction accuracy plus how many wrong actions it would have blocked.
- **Action validator gate — target-exists membership check** — A baked circuit content-addresses the proposed action's target id against the current element-id set (a membership/CAM fold on the Muhlnickel) and emits one bit: is the target actually present, enabled, and addressable on THIS live screen — catching hallucinated targets before actuation. *Try:* Build pfc_action_validate as a membership fold over the element-id set, run it against gauntlet action logs, and count how many emitted actions reference a non-present or disabled target.
- **Grounded tap-coordinate synthesis on the Muhlnickel (id → exact point)** — Instead of the model emitting error-prone pixel coordinates, it emits a compact element id and a baked geometry circuit computes the exact tap point from the element's bounds (center, clamped/offset for edge controls) on the Muhlnickel, removing coordinate tokens and a miss-tap class. *Try:* Bake pfc_tap_coord (bounds → point) as gates, route element-id → coords in MechanismRouter, and measure miss-tap rate plus action token count vs. model-emitted coordinates.
- **Perceptual-hash replay verification (predicted vs actual next screen)** — After acting, hash the resulting screen and compare it on the Muhlnickel (membership fold) to the world-model's predicted next-screen-hash; a mismatch means the action did not do what was expected, triggering an immediate re-plan instead of blindly continuing onto a screen the agent misreads. *Try:* Bake the predicted-vs-actual screen-hash comparator, log divergence events across the gauntlet, and measure how many downstream wrong actions a divergence-triggered re-plan prevents.
- **Agent reflex table (baked (screen-hash, intent) -> action LUT)** — System-1 for the LDA: the most common UI steps (tap a known control, dismiss a known dialog) resolve by an addressed LUT read keyed on perceptual-hash + intent — zero forward passes. The agent-loop analog of memoize, but baked as gates and keyed on perception, distinct from generic memoize and from constrained-decode masking. *Try:* Log frequent (screen-hash, intent, action) triples from real LDA runs, bake the top-N as a LUT circuit, and measure the percentage of steps served with 0 forward passes plus the latency drop on those steps.
- **Foveated / multi-resolution perception** — Perceive the screen coarse-first (a downsampled tile classifier on the substrate) to locate the intent-relevant region, then spend full-resolution perception only on that region of interest. Distinct from intent-conditioned element pruning (prunes elements) and temporal diff (across frames) — this is spatial multi-scale within one frame. *Try:* Build a two-stage perceive (coarse locate on a downsampled tile map -> fine read of the ROI) on real screenshots, and compare perception gate-evals and end-action accuracy vs single-scale full-frame perception.
- **Agent skill retrieval (RAG over a content-addressed skill library)** — Instead of the model reasoning a routine from scratch, retrieve a pre-verified action sequence from a content-addressed skill store (the membership/CAM fold applied to skills) keyed by intent, then execute/adapt it. Distinct from the single-step reflex table and from the world-model dry-run. *Try:* Build a CAM-indexed skill library keyed by intent embedding, retrieve top-k skills for a real task, and measure steps/forward-passes saved vs cold reasoning plus the success rate of the retrieved macro.
