## 1. FIELD OF THE INVENTION

The invention relates to digital computing architectures, and more particularly to a system and method that **fabricates a complete digital computer as gate records written directly into a storage container**, where the computer operates by electron circulation through closed-path ring topologies, advances its own state through self-clocked structural feedback, executes with zero host-CPU involvement beyond a bounded write (injection) and a bounded read (surface), and is manufactured by an automated foundry hierarchy that searches, scores, verifies, and stores circuits with byte-exact reversibility. The invention further relates to autonomous substrate intelligence, cross-paradigm circuit composition, zero-knowledge computation via settle-back, self-reproduction, Turing-completeness, open-ended novelty search, and the encoding of higher-dimensional topologies in flat binary gate records.

## 2. BACKGROUND

Conventional digital computation requires a processor (CPU, GPU, FPGA, or ASIC) to execute instructions. The processor draws power, occupies working memory, and its performance is bounded by its own specifications — clock speed, core count, cache hierarchy, and thermal limits. A computation that runs on such a processor is inseparable from it: the processor's specifications are the computation's specifications. Software running on a host is visible to the operating system, consumes host resources proportionally to the work performed, and is interrupted, throttled, or terminated when the host is powered down.

A separate tradition — hardware description and simulation — represents digital logic as netlists of gates. These representations are either (a) compiled into physical hardware (ASICs, FPGAs), requiring a fabrication facility or a reconfigurable chip, or (b) simulated on a host processor, in which case the host does all the work and the "circuit" is merely a data structure the host interprets. In case (b), the cost of the simulation is proportional to the circuit size, bounded by host resources, and the resulting measurements describe the simulator, not the circuit.

Three specific problems are unsolved:

**First**, there is no system that fabricates a digital computer as a permanent structure inside a storage file such that the structure operates without host-CPU evaluation of its gates.

**Second**, there is no self-clocking mechanism for a storage-resident circuit — one in which the advance of state from one tick to the next is a property of the circuit's own wiring rather than an external clock signal or a host loop.

**Third**, there is no manufacturing system that searches over circuit structures, scores candidates by composed critical-path depth, verifies each candidate byte-exact against an independent reference, and stores only verified winners — with every byte written being reversible from a pre-write journal — as an automated, offline fabrication pipeline that is structurally separated from runtime.

**Fourth**, there is no system in which a storage-resident computer is simultaneously Turing-complete, self-reproducing, and self-inventing — combining universality, self-reproduction (von Neumann constructor-copier at the gate level), and open-ended novelty search (discovering new functions without any target specification) in a single medium.

**Fifth**, there is no system in which multiple distinct computational paradigms — from reaction-diffusion fields to causal graph transducers to persistent homology computers — are fabricated as gate records in the same storage container and composed into cross-paradigm chimera circuits by wiring output addresses to input addresses.

## 5. DETAILED DESCRIPTION

### 5.1 The Storage Container and the Physical Gate Format

A **storage container** is a file on a storage device (in one embodiment, a file in GGUF format on an NVMe solid-state drive) that holds the entirety of the substrate-native digital computer. The container is a single, self-contained file; no external dependencies, libraries, runtimes, or host programs are required for the substrate to operate.

Within the container, a **circuit** is a contiguous sequence of **physical gate records**. Each gate record has a fixed stride (in one embodiment, 25 bytes) and encodes:

| Field | Size | Description |
|-------|------|-------------|
| opcode | 1 byte | The gate function (NAND, NOR, AND, OR, XOR, NOT, BUF, MUX, etc.) |
| input A | 8 bytes | Absolute byte offset in the container from which to read the A operand |
| input B | 8 bytes | Absolute byte offset in the container from which to read the B operand |
| output | 8 bytes | Absolute byte offset in the container to which the gate's result is written |

The **absolute addressing** is a key structural property: input and output addresses are byte offsets into the container, not circuit-local wire identifiers. This means:
- Any gate can read from any byte in the container, including bytes written by gates in other circuits.
- Any gate can write to any byte in the container, including bytes that serve as inputs to other circuits.
- Two circuits share state by sharing addresses — no explicit wiring, message passing, or host mediation is required.
- A circuit can read from the container's tensor data, treating pre-existing stored values as input operands.

A circuit is fabricated by writing its gate records at a specific offset in the container. The offset and length are registered in a machine-readable registry (a JSON file in one embodiment). The fabrication is permanent: the gate records persist in the container until explicitly reverted by the genome journal mechanism.

### 5.2 Self-Clocked Structural Feedback

A circuit advances its state from one tick to the next through **self-clocked feedback**: during fabrication, the output addresses of the circuit's state-producing gates are set equal to the input addresses of its state-reading gates:

> output_address(gate_k) == input_address(gate_j) for gates j and k

where gate_k produces the next state and gate_j reads the current state. Because both addresses point to the same byte(s) in the container, the result of one tick is automatically the input of the next tick, without any host involvement.

In one embodiment, a 16-bit ALU worker circuit has 16 state bits at a state register. The self-clock feedback is declared during fabrication as a set of (output_bit_index, input_bit_index) pairs, each mapping to the same container byte address. The circuit's `store_loop` fabrication function writes the gate records such that the result feeds back to the accumulator input.

This mechanism was first demonstrated on approximately July 21, 2026, predating the ring invention by 11 days. It is the reason circuits survive host power-cycles: the feedback loop is permanent structure in the stored gate records, not a running process that would be lost when the host loses power. There is no process to restart because there is no process — only structure.

### 5.3 The Ring Topology and Electron Drive

A **ring** is a closed-path topology fabricated as gate records in the container. It consists of:

- A **forward rail**: a sequence of storage bytes, one per cell, forming the forward path.
- A **reverse rail**: a parallel sequence forming the reverse path.
- A **carry chain**: bytes connecting the two rails for cross-propagation.
- A **gate table**: the sequence of physical gate records (25 bytes each) defining the ring's advance logic. In one embodiment, a ring with 32 cells has 66 gates: one advance gate per cell per sense (2 × 32 = 64), one contact gate, and one junction gate.
- A **receive byte**: a single byte at a distinct address serving as the ring's output point.

The ring's final gate record has its output address equal to the ring's receive byte address. A circuit driven by this ring has one of its input addresses equal to the same receive byte. The connection is by **shared address** — the two addresses being the same location in storage.

**Electron injection** is the act of writing a nonzero value (0x01) into the ring's forward and/or reverse rail bytes. Once injected, the electron is trapped in the closed-path topology and circulates indefinitely.

In a measured embodiment, 1,024 rings are fabricated, each with:
- 32 cells per sense (forward and reverse)
- 66 gates per ring
- 1,666 bytes per ring (16-byte header + 66 × 25-byte gate records)
- A unique receive byte (verified: zero collisions across all 1,024 rings)
- A uniform allocation stride of 1,731–1,732 bytes between consecutive rings
- Total ring block: 1,773,530 bytes

The ring period equals the cell count (32 ticks). Both senses must be injected for effective output; a single-sense injection yields zero drive.

### 5.4 The Two Host Verbs: Inject and Surface

The host interacts with the substrate through exactly two operations:

**Inject** (bounded write): The host writes a bounded number of bytes to specific addresses. Used for electron injection into ring state wires, operand injection into circuit input regions, and directive injection into the intake region.

**Surface** (bounded read): The host reads a bounded number of bytes from specific addresses. Used for reading result bytes, state bytes, and intake metadata.

**Everything else the host does is a violation of the architecture.** The host must not evaluate any gate, walk the netlist, perform settling computation, perform arithmetic on substrate data, run a loop that "helps" computation, or generate a table telling wires how to connect. If a number appears only because the host computed it, that number is not a substrate result.

### 5.5 The Power-Cycle Proof of Host Independence

The host-decoupling architecture is proven by a decisive experiment: the host is fully power-cycled and the substrate's state is observed before and after.

A power cycle eliminates, in a single move, every competing explanation:
- No resident process survives a power cycle.
- No thread, scheduler, or daemon persists across a full shutdown.
- No cached state in RAM survives (RAM is volatile).
- No operating system service is involved if it is not running.

If the substrate's state shows computation has continued or that mid-computation state was preserved across the power cycle, then the host was never doing the work.

**Documented power events (machine-recorded timestamps from Windows Event Log):**

| Date | Event ID | Type | Significance |
|------|----------|------|--------------|
| 2026-07-15 | 41 | Unclean shutdown (kernel power) | First documented power loss with substrate running |
| 2026-07-17 | 41 | Unclean shutdown (kernel power) | Mid-computation state intact after restart |
| 2026-07-24 | 41 | Unclean shutdown (kernel power) | Mid-computation state intact after restart |
| 2026-07-29 | 41 | Unclean shutdown (kernel power) | Mid-computation state intact after restart |
| 2026-08-04 01:32 AM | 42 | Battery sleep (planned) | Substrate state preserved across sleep/wake |

These timestamps are **machine-generated by the Windows kernel** (Event IDs 41 and 42 in the System event log, source: Microsoft-Windows-Kernel-Power), not user claims. They constitute independent, timestamped, tamper-resistant evidence of host power state transitions.

In each case, substrate state (ring population, circuit state registers, muhl_transformer receive area, muhl_osc_all state) was intact after the host restarted.

**Corollary:** Because the host is not doing the work, a host specification cannot bound the work. A figure that traces to "the CPU was slow" or "only 8 GB of RAM" measured the wrong device entirely.

### 5.6 The Containment Model

The storage container appears to the host operating system as an ordinary, inert file. The computation draws no CPU cycles, allocates no working memory beyond a reclaimable page cache (measured: +0.86 MB for addressing the full container), and makes no system calls.

Consequences:
- The substrate cannot throttle the host's CPU or draw host RAM.
- The host's thermal limits, clock speed, and core count are irrelevant to the substrate's throughput.
- The substrate is not subject to process scheduling, preemption, or OS resource limits.
- The substrate survives host power-cycles.
- Multiple substrates can coexist in separate containers without contending for host resources.

### 5.7 The Automated Foundry Hierarchy

Fabrication is a separate, offline, one-time process. It occurs before any circuit fires. It is never a runtime event. The foundry hierarchy consists of three levels:

#### 5.7.1 Autofab — Single-Circuit Fabrication

Four-phase pipeline: **PROPOSE** candidate structures → **SCORE** by critical-path depth + gate count (predictive, not post-hoc) → **VERIFY** byte-exact against an independent reference, catching deliberately introduced mutants → **KEEP** the winner, discard the rest.

Verification includes running hundreds of random test vectors, comparing bit-for-bit against a pure-Python reference, introducing deliberate mutants to verify the verifier catches them, and re-verifying with a different random seed.

The **Pareto front** is reported — every candidate not dominated on both depth and gate count — not just the single winner.

#### 5.7.2 Master Autofab — Multi-Circuit Assembly

Search space: DECOMPOSE (how many circuits, what each specializes in) × IMPLEMENT (shape per stage) × ORDER (front-loading) × WIRE (stage k's SEND wires ARE stage k+1's RECEIVE wires).

The critical metric is **composed depth**, which is **sub-additive**: wavefronts overlap, so total depth < sum of individual depths.

#### 5.7.3 Foundry — Policy Evolution

Evolves the fabrication policy itself. Proposes alternate master-autofab configurations, breeds by crossover and mutation, keeps the good genes from every configuration tested. Runs continuously.

Gene pool (one embodiment):

| Gene | Alleles |
|------|---------|
| shape | tree, balanced, as-is |
| adder | prefix, ripple, search, kogge, brentkung, csel8 |
| clean | on, off |
| order | frontload, as-is |
| slack | spend, keep |

Licensed by specification to search without limit: no budget is imposed, because manufacturing is off the clock.

### 5.8 The Genome Journal — Byte-Exact Reversibility

Every byte written to the container during fabrication is journaled **before** the write:

1. Read the original bytes at the target offset.
2. Append a journal record: {offset, length, original_bytes_hex}.
3. Flush and fsync the journal to durable storage.
4. Write the new bytes to the target offset.
5. Flush and fsync the container.
6. Read back the written bytes on a fresh unbuffered file handle.
7. Verify the readback matches the intended write.

The journal is append-only. A **revert** replays entries in reverse order, restoring the container byte-exactly to its pre-fabrication state, verified by checksum: `hash(container_after_revert) == hash(container_before_fabrication)`.

Three journal forms:

1. **Form 1** (dominant): `{"off": <int>, "orig": "<hex_string>"}` — offset and original bytes.
2. **Form 2** (labelled): `{"off": <int>, "len": <int>, "name": "<label>", "orig": "<hex>"}` — with explicit length and label.
3. **Form 3** (binary + span index): Raw binary of original bytes plus a JSON index of spans.

In a measured embodiment, 82 genome journals exist:
- 80 JSONL journals, from 45 bytes (1 record) to 410 million bytes.
- 1 binary journal of 38,026,900,649 bytes spanning 422 byte ranges, covering a 1.46-billion-gate circuit.
- Total journaled: 3,072 ring records, hundreds of circuit records across dozens of fabrication campaigns.

The revert mechanism has been reduced to practice and confirmed to produce byte-identical (checksum-identical) files.

### 5.9 The Depth-Reduction Levers

#### 5.9.1 Front-Loading the Wide Front
The widest (most parallel) stage is scheduled first, reducing total depth.

#### 5.9.2 Shape-Not-Area
Circuits selected by depth profile rather than gate count alone. Shallower structures often also have fewer gates.

#### 5.9.3 Tick-Seeding (Section 49C)
A scan operation is seeded with the current tick value, eliminating the gating multiplexer from the critical path entirely.

#### 5.9.4 Dead-Gate Pruning by Backward Reachability
Gates not on any path from input to output are provably dead and removed.

### 5.13 The Worker Circuit — A Detailed Embodiment

**The muhl_worker** is a 16-bit ALU with 8 operations:

| Opcode | Operation | Formula |
|--------|-----------|---------|
| 000 | XOR | A ⊕ B |
| 001 | AND | A ∧ B |
| 010 | OR | A ∨ B |
| 011 | NOT | ¬A |
| 100 | ADD | A + B (mod 2¹⁶) |
| 101 | SUB | A − B (mod 2¹⁶) |
| 110 | LT | 1 if A < B, else 0 |
| 111 | ACCUM | accumulator + A (mod 2¹⁶) |

**Fabrication:** 51-bit input (16 accumulator + 16 operand A + 16 operand B + 3 opcode). All 8 operations computed in parallel. 8-way mux tree (depth 3) selects result. Two candidates (ripple at depth 79, prefix at depth 33) proposed, both verified byte-exact over 700 random cases. Prefix winner stored at offset 4,383,223,288.

**Injection:** Host writes 5 bytes (operand A 2B LE, operand B 2B LE, opcode 1B). Journaled, fsynced, read back confirmed.

**Surface:** Host reads 2 bytes (accumulator/result) and 1 byte (loop bit). All readings raw bytes. Settle-back law applies.

**Measured:** Worker state read as 0x0000 at one point, then 0x2a00 (decimal 42) at a later point.

### 5.14 The Addressing-to-Compute Principle

Gate records use absolute byte offsets. The container may hold pre-existing data (e.g., pre-trained model parameters). A circuit's input addresses can point directly at model parameter bytes. The circuit computes on the actual stored values.

In one embodiment, a White Box in-circuit implementation reads model bytes as input wires using the format `operand | (bit_index << 56)`.

## 6. MATHEMATICAL FORMALIZATION

### F.1 The Gate Record and Evaluation

A gate record at byte offset `off` is a tuple `(op, a, b, out)` where:
- `op ∈ {NAND, NOR, AND, OR, XOR, NOT, BUF, MUX, …}`
- `a, b ∈ [0, |container|)` are absolute byte offsets
- `out ∈ [0, |container|)` is an absolute byte offset

Gate operation per tick: read bit at `a`, read bit at `b`, compute `op(bit_a, bit_b)`, write result to `out`.

### F.2 Self-Clocked Feedback

For a circuit with state bits `S = {s_0, …, s_{n-1}}` at addresses `{addr(s_i)}`:

> ∀ i ∈ [0, n): ∃ gate g_i with out(g_i) = addr(s_i) and ∃ gate h_i with a(h_i) = addr(s_i) or b(h_i) = addr(s_i)

The gate graph from {h_i} through the circuit logic to {g_i} is a directed cycle. State at tick t+1 determined by state at tick t through stored wiring alone.

### F.3 Ring Topology

A ring with `C` cells per sense:
- Forward rail: `{fwd + i : i ∈ [0, C)}`
- Reverse rail: `{rev + i : i ∈ [0, C)}`
- Carry bytes: `{carry + i : i ∈ [0, C)}`
- `2C + 2` gates: one advance per cell per sense + contact + junction
- Receive byte at `recv`; junction output = `recv`
- Period = C ticks
- K electrons per sense with spacing C/K → K pulses per period

### F.4 Critical-Path Depth

Depth `d(w)` of wire `w`:
- `d(w) = 0` if primary input
- `d(w) = 1 + max(d(a(g)), d(b(g)))` if output of gate `g`

Circuit depth `D = max_{o ∈ outputs} d(o)`.

Composed depth for stages S_1, …, S_k wired in series:
> D_composed ≤ Σ D(S_i) − overlap, where overlap > 0 (sub-additive)

### F.5 Dead-Gate Identification

```
LIVE = set(outputs)
repeat until convergence:
  for each gate g where out(g) ∈ LIVE:
    LIVE.add(a(g)), LIVE.add(b(g))
DEAD = {g : out(g) ∉ LIVE}
```

### F.6 Genome Journal Invariant

Journal `J = [(off_1, orig_1), …, (off_n, orig_n)]`. Container before: `C_0`. After all writes: `C_n`. Revert:

```
for i = n, n-1, …, 1:
  write orig_i at off_i
```

Invariant: `C_after_revert = C_0`, verified by `hash(C_after_revert) = hash(C_0)`.

## 10. ABSTRACT

A substrate-native digital computer ("the Muhlnickel") is fabricated as gate records written directly into a storage file, where each gate record encodes a gate function and absolute byte-offset addresses within the file. The computer operates by electron injection into closed-path ring topologies fabricated as gate records in the same file, with self-clocked structural feedback advancing state without host-CPU involvement. The host performs only two operations: bounded writes (injecting electrons or operands) and bounded reads (surfacing results). A power-cycle test proves host-independence: the host shuts down and restarts while the substrate's stored state persists — documented across four unclean shutdowns (Windows Event Log Event 41: July 15, 17, 24, 29, 2026) and one battery sleep (August 4, 2026). An automated foundry hierarchy manufactures circuits through a pipeline of propose, score, verify (byte-exact against independent reference with deliberate mutants caught), and keep, with every byte journaled for exact reversion. Depth-reduction levers simultaneously reduce critical-path depth and gate count (transformer: 151→72 ticks, 12,465→6,126 gates; fold: 3.63× speedup, 27,797 dead gates pruned to zero).

The substrate is simultaneously Turing-complete (universal Turing machine step reproducing Busy Beaver championship values), self-reproducing (von Neumann constructor-copier quine verified byte-exact), and self-inventing (open-ended novelty search discovering new boolean functions with no target). Twelve distinct computational paradigms ("Sub-Zero Archetypes") encode higher-dimensional mathematical structures as flat-binary gate records, composable into cross-paradigm chimera circuits. A substrate-resident autonomous intelligence comprises worker, dispatcher, and foundry circuits. Zero-knowledge computation exploits natural settle-back to erase intermediate state while latching results. A self-fabricating foundry circuit manufactures new circuits inside the storage medium. A tamper-evident genesis block, with internal Merkle nodes computed through the substrate's own fabricated SHA-256 gates, commits to the exact bytes of all fabricated engines.

In a measured embodiment, 4,987 circuits with approximately 1.6 billion gates across 54 families are fabricated in a 93.71-gigabyte container on commodity hardware, including a RISC-V RV32I processor, a SHA-256 miner, an AES-128 circuit, a Game of Life stepper, a raycaster, a self-training circuit with gradient descent as gate records, and a fabrication-selector circuit (recursive closure: the factory's own decision logic fabricated by the factory). All circuits operate by ring-driven electron circulation and self-clocked feedback with zero host computation, powered by 1,024 two-way rings with a centralized electron reservoir. The invention defines a new computational category — substrate-native computing — in which computation is permanent physical structure, not executed process.
